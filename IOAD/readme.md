## Запуск работ 4–7

Проверено с Python 3.11.9. В `requirements.txt` записаны версии библиотек этого запуска.

```powershell
cd D:\BSTU\7sem\IOAD
python -m pip install -r requirements.txt
python lab4\lab4.py
python lab5\lab5.py
python lab6\lab6.py
python lab7\lab7.py
```

Окна с рисунками открываются в конце каждой работы. Закройте их, чтобы перейти к следующей команде. Рисунки одновременно сохраняются в папку работы. Для запуска без окон задайте переменную соответствующей работы, например:

```powershell
$env:LAB5_NO_SHOW='1'
python lab5\lab5.py
Remove-Item Env:LAB5_NO_SHOW
```

Аналогично работают `LAB4_NO_SHOW`, `LAB6_NO_SHOW` и `LAB7_NO_SHOW`. Работа 5 дольше остальных из-за перебора параметров и кросс-валидации.

## Готовые IT-вакансии (работы 4–7)

Все четыре работы читают только `hh-data/it_vacancies.csv`: **5790 строк, 63 числовых признака**, без пропусков. `publication_date` и текстовая `role` — служебные столбцы; роль уже представлена через `role_*`. В работах 4, 5 и 7 цель `overloaded`: класс 1 — от 100 откликов на момент сбора, класс 0 — меньше 100. Счётчики откликов в признаки не входят. В работе 6 целевая метка исключена: ищутся группы похожих вакансий.

Разбиение для классификации одинаковое: `train_test_split(test_size=0.2, stratify=y, random_state=42)`, train — 4632 строки, test — 1158. В работе 5 параметры выбираются по пяти стратифицированным CV-разбиениям внутри train.

Кодирование категорий, заполнение пропусков и стандартизация трёх непрерывных признаков выполнены заранее. В работах 4–5 повторной подготовки нет. В работе 6 оставлен один `MinMaxScaler`, прямо требуемый заданием; в работе 7 `StandardScaler` используется для сравнения PCA на шкалах готового CSV и после стандартизации всех столбцов. Заполнение пропусков, извлечение признаков и повторное кодирование в лабораторных не выполняются.

**Ограничение оценки:** готовый CSV подготовлен по всей выборке до разделения. Поэтому test не полностью изолирован от решений предобработки. Это учебное сравнение на готовых данных, а не проверка прогноза для будущих публикаций или новых работодателей. Возраст вакансии известен на момент сбора, а не при публикации.

Сырой `hh-data/hh_vacancies_2026_07.csv` нужен только для однократной сборки через `hh-data/build_it_dataset.py`; при обычном запуске лабораторных он не читается и не скачивается. [Описание источника и сборки](hh-data/readme.md). Прежние данные DotaScience остаются в `dota-data` для архивных версий.

Большие исходные CSV (hh.ru и DotaScience) и старые BNPL CSV исключены из Git общими правилами репозитория. Небольшие итоговые таблицы работ 4–7 разрешены локальным `.gitignore`.

## Работа 8: предобработка изображений

В `lab8` реализованы бинаризация, выравнивание гистограммы, три фильтра и морфология одним последовательным скриптом. Включены демонстрационные фотографии с указанием источников; пути к собственным снимкам задаются в начале скрипта. Зависимости — в отдельном `lab8/requirements.txt`.

```powershell
.\.venv\Scripts\python.exe -m pip install -r lab8\requirements.txt
.\.venv\Scripts\python.exe lab8\lab8.py
```

Сравнительные рисунки и отдельные обработанные изображения сохраняются в `lab8/output`; переменная `SHOW_PLOTS = False` отключает показ окон. [Запуск, объяснения и ответы на 11 вопросов](lab8/readme.md).
