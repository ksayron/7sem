# ПВС, лабораторная работа № 2: JSON-RPC

`JSONRPCServer` — ASP.NET Core Web API (.NET 10), `client` — консольный клиент на Go. Внешних NuGet-пакетов и Go-модулей нет. Сервер использует `System.Text.Json`, клиент — `net/http` и `encoding/json`.

## Запуск в двух терминалах

Нужны .NET SDK 10 и Go 1.22 или новее. Команды для PowerShell.

Первый терминал — сервер:

```powershell
cd D:\BSTU\7sem\PWS\lab2
dotnet run --project .\JSONRPCServer
```

Сервер слушает `http://127.0.0.1:8200`, JSON-RPC endpoint — **POST `/rpc`**, Content-Type — `application/json`. GET `/` выводит название сервиса и список процедур.

Второй терминал — Go-клиент:

```powershell
cd D:\BSTU\7sem\PWS\lab2\client
go run .
```

Клиент печатает исходящий JSON (`-->`) и ответ (`<--`): все пять процедур с позиционными и именованными параметрами, деление на ноль, переполнение факториала, смешанный пакет, уведомление и некорректный JSON. Рядом с каждым примером указан ожидаемый результат.

Отдельные подготовленные запросы:

```powershell
go run . -file ..\examples\sum.json
go run . -file ..\examples\batch.json
```

В `examples/batch.json` можно редактировать параметры. Пакет содержит пять успешных вызовов, две ошибки и одно уведомление. В ответе будет массив из семи элементов: `5`, `7`, `12`, `3.5`, `120`, ошибка `-32001` и ошибка `-32002`. Сопоставлять ответы следует по `id`.

Для произвольного endpoint используйте `-url http://127.0.0.1:8201/rpc`; для JSON непосредственно в аргументе — `-request '<JSON>'` (с учетом правил экранирования вашей оболочки).

## Процедуры и параметры

| Сигнатура | Позиционные `params` | Именованные `params` | Результат |
| --- | --- | --- | --- |
| `double SUM(double x, double y)` | `[10.5, 2.5]` | `{"x":10.5,"y":2.5}` | `13` |
| `double SUB(double x, double y)` | `[10, 3]` | `{"x":10,"y":3}` | `7` |
| `double MUL(double x, double y)` | `[2.5, 4]` | `{"x":2.5,"y":4}` | `10` |
| `double DIV(double x, double y)` | `[7, 2]` | `{"x":7,"y":2}` | `3.5` |
| `int FACT(int x)` | `[5]` | `{"x":5}` | `120` |

Порядок полей именованного объекта произвольный. Имена методов и параметров чувствительны к регистру: `SUM`, `x`, `y`. Количество параметров должно совпадать с сигнатурой, лишние поля и повторяющиеся имена параметров отклоняются. Параметры передаются JSON-числами, строки `"5"` не преобразуются в числа. Для `FACT` требуется целое JSON-число в диапазоне Int32: отрицательное значение дает ошибку параметров, `0! = 1`, `12! = 479001600`, начиная с `13!` — ошибка переполнения. Для остальных процедур принимаются конечные значения `double`; бесконечный результат возвращается как ошибка.

## Формат протокола

Реализация использует [JSON-RPC 2.0](https://www.jsonrpc.org/specification). Пример вызова:

```json
{"jsonrpc":"2.0","method":"SUM","params":{"y":2.5,"x":10.5},"id":1}
```

Ответ:

```json
{"jsonrpc":"2.0","result":13,"id":1}
```

Ошибка деления на ноль:

```json
{"jsonrpc":"2.0","error":{"code":-32001,"message":"Division by zero"},"id":1}
```

| Код | Значение |
| --- | --- |
| `-32700` | Некорректный JSON |
| `-32600` | Некорректная структура запроса, `id` или пустой пакет |
| `-32601` | Неизвестная процедура |
| `-32602` | Неправильные параметры, типы, отрицательный аргумент FACT |
| `-32603` | Внутренняя ошибка сервера |
| `-32001` | Деление на ноль |
| `-32002` | Факториал превышает `Int32.MaxValue` |
| `-32003` | Результат арифметики выходит за диапазон конечных `double` |

Обычные JSON-RPC результаты и ошибки передаются с HTTP 200, а ошибка описывается полем `error` в JSON. Поля `result` и `error` взаимоисключающие. Идентификатор `id` возвращается без изменения, включая строку, число или явный `null`.

Запрос **без поля `id`** — уведомление: процедура выполняется, ответного JSON нет, HTTP 204. Это относится и к уведомлениям, при выполнении которых возникает ошибка. Пакет — непустой JSON-массив запросов; каждый элемент обрабатывается независимо и последовательно. Ошибка одного элемента не прерывает остальные. Ответ содержит только результаты вызовов с `id` и ошибки некорректных элементов. Для пакета только из уведомлений — HTTP 204 без тела, для пустого массива `[]` — один объект ошибки `-32600`.

## Где смотреть код при защите

- `JSONRPCServer/Program.cs` — маршрут `/rpc`, чтение JSON, ошибка разбора и HTTP 204.
- `JSONRPCServer/RpcDispatcher.cs` — проверка конверта, связывание параметров, выбор процедуры, пакетная обработка, сохранение `id`, формирование ответа.
- `JSONRPCServer/Arithmetic.cs` — пять процедур и проверки деления на ноль / переполнения.
- `client/main.go` — HTTP-клиент и аргументы запуска; `demo.go` — демонстрационные вызовы.
- `client/integration_test.go` — проверка обоих способов передачи параметров, граничных значений, ошибок, идентификаторов, уведомлений и пакетов.

При демонстрации сначала покажите один запрос с массивом `params`, затем аналогичный с объектом `params`, ошибки `DIV(1,0)` и `FACT(13)`, после этого отправьте `examples/batch.json` одним HTTP-запросом и объясните семь ответов на восемь элементов.
