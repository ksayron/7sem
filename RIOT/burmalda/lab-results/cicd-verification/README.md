## Проверка приложения после выпуска

Verify открывает port-forward к `service/web` внутри агента и выполняет семь
настоящих HTTP-проверок:

1. Клиент и конфигурация функций.
2. Авторизация, валидация, ответы Not Found и Forbidden.
3. Отсутствие маршрутов Gateway к отключённым учебным сервисам.
4. Параллельное создание шести экземпляров и согласованная поисковая проекция.
5. Книга, экземпляр, Saga, выдача по коду, возврат и обновление проекции.
6. Два конкурирующих заёмщика: один экземпляр — один победитель.
7. Уведомления и репутация.

Файлы `build-N.json` содержат сводку фактических Jenkins API, JUnit, release,
images, load и HTTP-артефактов. Статус `SKIPPED` уточнён по Console Output:
Jenkins Stage View API может наследовать FAILED для пропущенного этапа.
Полные TRX/JUnit, логи и снимки доступны в артефактах соответствующей сборки.
Пароли, kubeconfig, пользовательские токены и приватные шаблоны Deployment
в этот журнал не включены.

Сборки #1–5 относятся к первоначальной настройке окружения и доступа агента;
первый подтверждённый полный выпуск — #6. #6 выполнялась на временном агенте
с теми же инструментами и правами; начиная с #7 используется собранный
`burmalda-ci-agent:lr10` с официальным kubectl 1.34.1 и проверенной SHA-256.
