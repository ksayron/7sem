# Проверка демо · 13 ноября 2026

Среда: Docker Desktop, Kubernetes 1.34.1, один узел, Windows с 16 ГиБ RAM.
Результаты относятся к этому компьютеру и описанному сценарию.

## Реально проверено

- 29 тестов DemoControl и 60 существующих тестов домена проходят. Сборка без предупреждений.
- Основной бизнес-процесс: 7 проверок, включая выдачу, передачу, возврат, проекцию и конкурирующие заявки (`core/integration.json`).
- 300 отдельных аккаунтов подготовлены через Gateway. Смешанный профиль завершил реальные операции без оставшихся выдач (`safety.json`).
- Ограничение одновременных запусков, ручное изменение нагрузки, обычная и аварийная остановка, повторные команды.
- 100% ошибок Catalog затронули обычный API сайта; через 15 секунд сбой истёк при выключенном DemoControl. После запуска PVC сохранил аккаунты и прерванный запуск; нагрузка не возобновилась (`safety.json`).
- Полный recovery-пресет: 300 клиентов, рост 90 с, удержание 120 с. Сценарий продолжался 420 с. HPA увеличил Catalog с 1 до 4 и Gateway с 1 до 3. Старый UID исчез, новый Catalog Pod достиг Ready. Временный сбой 25% ответов истёк. Оба сервиса вернулись к одному Ready Pod без команд масштабирования.
- Снижение завершилось к 7:33 от начала, примерно через 33 секунды после завершения сценария. Для живого показа оставить около восьми минут вместе с наблюдением последней реплики.
- Максимум среди сохранённых 30-секундных окон с p95 ≤ 1 с и ошибками < 1%: **150,4 успешных RPS**. Это наблюдённое значение, не найденный предел производительности (`result.json`).
- Новые Pod получали HTTP-трафик (`pod-traffic.json`). Повторный `Start -Demo` сохранил реплики 4/3 (`repeat-start.json`).
- Prometheus принимает OTLP HTTP/.NET, kubelet CPU/RAM и kube-state-metrics. Все 21 выражение 15 панелей Grafana выполняются без ошибок; отсутствие series операций после отдельного чтения ожидаемо (`dashboard-queries.json`, `grafana.png`).
- Пульт 1440×1000 и 390×844: вход с клавиатуры, CSRF, отсутствие горизонтального переполнения и ошибок JavaScript (`ui.json`, снимки пульта). Недоступность Prometheus отображалась явно до запуска мониторинга.
- Реальный обрыв отдельного port-forward показал окно переподключения Blazor; восстановление соединения и перезагрузка вернули пульт (`connection.json`, `connection-loss.png`). Основные port-forward при этой проверке оставались доступны.
- ServiceAccount пульта не может обновлять `deployments/scale`, но может удалять Pod; это проверено через `kubectl auth can-i`.

## Воспроизведение проверки

`node tools/verify-demo.cjs` собирает свежие измерения. Проверка восстановления ищет Ready замены в течение запуска: HPA вправе позднее удалить именно этот экземпляр. В первом прогоне проверка ошибочно требовала сохранения замены до самого конца; это исправлено, исходный диагностический `failed.json` оставлен. Сохранённые samples и финальное состояние успешно проверены исправленной проверкой `node tools/verify-demo-evidence.cjs`.

`result.json` содержит измерения, графики, события и результаты проверки. `final-state.json` — финальное состояние без токенов. Подготовленные аккаунты и SQLite остаются на PVC.
