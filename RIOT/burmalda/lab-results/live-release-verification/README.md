# Живой выпуск под нагрузкой — ЛР9 + ЛР10

Проверено 17 ноября 2026 года (Europe/Minsk), Docker Desktop Kubernetes,
один узел. Пульт ЛР9 и мониторинг продолжали работать отдельно от восьми
обновляемых прикладных компонентов.

## Фактический сценарий

1. Исходный выпуск [Jenkins #16](http://localhost:8081/job/burmalda-lab10/16/)
   получил SUCCESS; Catalog передаёт редакцию 1, коммит `17b5865e6fee`.
2. Браузер вошёл существующим администратором, подготовил 20 тестовых читателей
   и запустил сценарий «Обновление работающей библиотеки».
3. Браузер нажал настоящую кнопку «Выпустить обновление». Мост увеличил C#-константу
   `ReleaseEdition.Number` до 2 в отдельной Git-копии и отправил коммит
   `2f1de18b3fdcadc2fcbff2c7b030b6394738f21c` в `demo/live-release`.
4. Poll SCM запустил [Jenkins #17](http://localhost:8081/job/burmalda-lab10/17/).
   Все этапы завершились SUCCESS. Выполнены 182 теста: 177 Unit,
   четыре интеграционных и один нагрузочный, без ошибок и пропусков.
5. Восемь компонентов последовательно перешли на
   `ci-17-2f1de18b3fdc`; читатели продолжали читать, брать и возвращать книги.

поэтому сумма ответов двух редакций Catalog меньше общего числа запросов.
Изменяющие запросы не повторяются автоматически. Внешний клиент не применяет retry.
После проверки нагрузка остановлена с завершением операций; приложение и пульт
оставлены доступными для следующего показа.

## Артефакты

- `result.json`: номер сборки, SHA, времена этапов, ответы версий, ошибки и операции.
- `timeline.json`: снимки Pod, числа читателей, операций и HTTP-наблюдений.
- `tests.json`, `release.json`, `images.json`: фактические артефакты Jenkins #17.
- `release-desktop.png`, `release-mobile.png`: реальный пульт во время Deploy.
- `initial-ui/ui.json`: вход с клавиатуры, CSRF и desktop/mobile без переполнения.

Для команды выпуска дополнительно подтверждены HTTP 401 без входа,
HTTP 400 для cookie без CSRF, HTTP 401 для моста без ключа и HTTP 404 для
неразрешённого маршрута моста. Локальные DemoControl-тесты после исправления
подготовки токенов: 32 Passed, 0 Failed, 0 Skipped.

Это наблюдение на указанной нагрузке и совместимом обновлении, а не обещание
нулевого простоя при произвольной миграции БД или отказе единственного узла.
Команды запуска и повторения — [в инструкции](../../docs/live-release-demo.md).
