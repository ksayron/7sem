# ЛР10: Jenkins CI/CD

Лабораторная сдаётся отдельно от ЛР9. Предметная область — обмен книгами Burmalda.
Jenkins получает код из GitHub, проверяет его, собирает образы и автоматически
обновляет восемь компонентов в Docker Desktop Kubernetes.

## Подготовка и запуск

Нужны Docker Desktop с работающим одноузловым Kubernetes `docker-desktop`,
PowerShell 7.4+, Python 3.11+ и Git. Кластер, образы инфраструктуры, Secret и PVC
сохраняются от ЛР9. Установка Java и .NET на Windows для Jenkins не требуется:
Java 21 находится в контейнерах, SDK — в сборочном агенте.

Из `RIOT/burmalda`:

```powershell
./tools/Jenkins.ps1 Prepare
./tools/Jenkins.ps1 Build
./tools/Jenkins.ps1 Start -Branch master
./tools/Jenkins.ps1 Run
./tools/Jenkins.ps1 Status
```

`Prepare` поднимает базовые компоненты, сохраняет существующие данные и образы
Deployment, создаёт namespace-scoped ServiceAccount и выдаёт ему токен на семь
дней. Повторите Prepare для обновления токена. При обновлении токена работающему
агенту перезапуск не нужен. Подготовка возвращает базовый ConfigMap ЛР9;
не запускайте её одновременно с экспериментами старого демо.

Jenkins: <http://localhost:8081/job/burmalda-lab10/>. Пользователь `admin`,
пароль находится в `.artifacts/ci/secrets/admin-password`. Этот каталог содержит
также kubeconfig и секрет агента; он игнорируется Git и не входит в артефакты.
Jenkins привязан к loopback. Агент имеет Docker socket для работы с локальными
образами; это доверенное локальное учебное окружение.

`Start -Branch lab10/cicd` переключает задание на ветку экспериментов.
Контроллер имеет ноль исполнителей, агент — один; параллельные выпуски запрещены.
При пересоздании контейнеров история и рабочее пространство сохраняются в volumes.
Образы Jenkins/Java/.NET и версии плагинов зафиксированы; загрузчик плагинов
проверяет SHA-256 каждого файла. Обновления выполняются отдельным изменением lock-файла.

Для нестабильной сети Build временно запускает локальный кэш загрузки на порту
18089: большие файлы скачиваются небольшими диапазонами с повторными попытками.
Кэш разрешает только публичные Debian/Kubernetes downloads; TLS, подписи APT и
контрольная сумма kubectl проверяются. `Build -DirectDownloads` отключает кэш.
После сборки запущенный скриптом сервер завершается.

Jenkins получает `RIOT/burmalda/Jenkinsfile` через Pipeline from SCM. Poll SCM
проверяет Git каждые две минуты и учитывает изменения `RIOT/burmalda`.
Первую сборку запускают вручную; она регистрирует расписание из Jenkinsfile.
Публиковать исходники следует обычным Git push с компьютера: Jenkins для checkout
публичного репозитория не нужны ваши GitHub credentials.
Локальное read-only Git-зеркало ускоряет checkout большого учебного репозитория;
ветка и SHA по-прежнему определяются состоянием GitHub.

## Этапы и условия выпуска

| Этап | Действие | Условие перехода |
|---|---|---|
| Checkout | Чистый checkout, SHA, проверка инструментов и прав | Доступны Docker и namespace |
| Restore | `dotnet restore Burmalda.slnx -m:1` | Зависимости восстановлены |
| Build | Release, `--no-restore`, последовательная сборка | Нет ошибок компиляции |
| Test | Domain, LibraryGame, Raft, DemoControl и Catalog integration | Все тесты выполнены без пропусков и ошибок |
| Load | Восемь работников, 20 циклов reserve/release, реальный PostgreSQL | 320 операций, все инварианты сохранены |
| Package | Восемь образов существующим Dockerfile | Каждый образ собран и проинспектирован |
| Deploy | Обновление образов, аннотации SHA/build, ожидание rollout | Все Deployment готовы |
| Verify | Контроль реальных Pod и HTTP через Service | Полный предметный сценарий успешен |

Тестовые PostgreSQL/RabbitMQ живут в отдельной сети, без host ports и volumes
приложения. Их имена включают номер сборки. После сборки контейнеры, их анонимные
volumes и сеть удаляются. Пропущенные интеграционные тесты считаются ошибкой CI.
Нагрузочная проверка измеряет время, но проверяет корректность, без нестабильного
порогового значения производительности для ноутбука.

Теги `ci-<BUILD_NUMBER>-<SHA12>` уникальны для сборки. OCI labels содержат полный
SHA. Package и Kubernetes используют один Docker Engine; успешный старт Pod
подтверждает доступность образа кластеру. DinD и внешний registry не используются.

Verify проверяет новые образы и Ready-контейнеры, открывает временный port-forward
к `service/web` внутри агента и запускает `tools/verify-core.cjs`: регистрация,
книга, экземпляры, Saga, выдача, возврат, конкурирующие заёмщики, уведомления и
репутация. Port-forward завершается даже при ошибке.

Ошибка обязательного этапа даёт **Failed**. После ошибки Build/Test/Load новые
образы не создаются и приложение не обновляется. После ошибки Deploy/Verify
сохраняются события/состояния ресурсов и восстанавливаются прежние шаблоны
обновлённых Deployment. Rollback также проверяет rollout; его ошибка видна в отчёте.
Выпуск нескольких микросервисов не является атомарной транзакцией, поэтому
обновления требуют совместимости контрактов и схем. ЛР10 схемы БД не меняет.

## Результаты и эксперименты

В Jenkins доступны граф этапов, Console Output, Test Result и архив:
`release.json`, `images.json`, JUnit/TRX, `load.json`, снимки ресурсов,
`acceptance/integration.json`, а при ошибке — диагностика и `rollback.json`.
Токены пользователей предметной проверки и полные шаблоны Deployment остаются
только во внутреннем игнорируемом каталоге.

Порядок обязательного эксперимента в `lab10/cicd`:

1. Опубликовать рабочую реализацию и получить Success.
2. Изменить исходный код, push, проверить новый SHA и новые образы.
3. Временно изменить ожидаемое значение настоящего Unit-теста, commit/push.
4. Получить Failed на Test; проверить, что Package/Deploy пропущены и SHA
   работающего приложения не изменился.
5. Восстановить тест отдельным коммитом, push и получить Success.
6. Отдельно проверить остановку при ошибке компиляции и откат при недоступном
   образе; восстановить рабочую ветку и повторить успешный выпуск.

Фактические номера сборок и результаты приведены в
[журнале проверки](../lab-results/cicd-verification/README.md).

## Остановка и доступ к приложению

```powershell
./tools/Jenkins.ps1 Stop
./tools/Kubernetes.ps1 Access -Background
# http://localhost:5300
./tools/Kubernetes.ps1 Stop
```

Остановка Jenkins сохраняет историю; остановка Kubernetes сохраняет PVC и Secret.
Не удаляйте volumes для обычной остановки лабораторной.

CI — автоматическая проверка изменений. Continuous Delivery — подготовка
проверенного артефакта к выпуску с возможным ручным решением. Этот Pipeline
после тестов автоматически обновляет Kubernetes и реализует Continuous Deployment.
