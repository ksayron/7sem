# Лабораторная №8 — ORM Hive

Отдельное Flutter-приложение магазина кофе на основе лабораторной 4–5. Сохранены тёмная тема, оранжевые акценты, изображения, поиск, категории, сортировка, экран напитка и настройка размера/количества. Товары, пользователи и избранное теперь сохраняются в Hive. Предыдущие лабораторные не изменены.

## Запуск

Открыть **папку lab8**, а не её подпапку `android`.

```powershell
cd D:\BSTU\7sem\PMP\lab8
flutter pub get
.\tools\run-android.ps1
# Если эмулятор уже работает:
.\tools\run-android.ps1 -DeviceId emulator-5554
```

Скрипт выбирает подготовленные SDK `D:\Android\sdk-coffee`, Gradle `D:\Android\gradle-coffee`, JDK Android Studio и временную папку на D:, если они существуют. Перед запуском он проверяет `sys.boot_completed`, package manager и activity service. На другом компьютере достаточно установить Flutter/Android SDK, запустить устройство и выполнить `flutter run -d <device-id>`.

Идентификатор Android: `by.bstu.coffee_lab8`. Приложение устанавливается отдельно от других лабораторных. Готовый debug APK: [deliverables/coffee-lab8-debug.apk](deliverables/coffee-lab8-debug.apk).

## Пользователи и сценарий защиты

При первом запуске создаются **Alex / admin**, **Emma / user**, **Daniel / user** и семь напитков. Приложение открывается на экране входа. Доступны учебные локальные учётные записи:

| Пользователь | Логин | Пароль | Роль |
|---|---|---|---|
| Emma | `emma` | `emma123` | user |
| Daniel | `daniel` | `daniel123` | user |
| Alex | `admin` | `admin123` | admin |

На экране входа есть обязательные поля, показ/скрытие пароля, автозаполнение, переход с клавиатуры, индикатор выполнения и ошибки. Подсказка `Demo accounts` содержит данные для демонстрации. Логин не зависит от регистра и пробелов по краям; пароль проверяется точно.

`Profile` открывает полноценный профиль с именем, логином, ролью, количеством избранного и переходом к нему. Кнопка `Sign out` вызывает подтверждение; `Stay signed in` отменяет выход. После выхода открывается чистая форма входа, история маршрутов удаляется. Кнопка «Назад» не возвращает в старую сессию. Товары и избранное сохраняются.

Активная сессия хранится в зашифрованном `settings` и восстанавливается при перезапуске; выход также сохраняется. При обновлении со старой версии без паролей потребуется один раз войти заново, данные остаются. Это учебная локальная авторизация с публичными демопаролями и фиксированными SHA-256-отпечатками в коде, без регистрации и сетевого сервиса идентификации.

1. Войти как Emma (`emma` / `emma123`), открыть Espresso, показать изображение, расположение, описание, рейтинг, отзывы и цену. Добавить в избранное и открыть `Favorites`.
2. В `Profile` нажать `Sign out`, подтвердить и войти как Daniel. Его список пуст. Добавить другой напиток, затем вернуться к Emma: её список независим.
3. Через выход и повторный вход выбрать Alex (`admin` / `admin123`), нажать `Add product`, заполнить название, цену, расположение, описание, рейтинг и отзывы; выбрать категорию и картинку. Пустые поля, нулевая цена, рейтинг вне 0–5 и отрицательное число отзывов не принимаются. Цена допускает точку или запятую и не более двух знаков после разделителя.
4. Найти новый товар поиском, открыть, нажать `Edit product`, изменить цену и описание. После сохранения карточка обновится. В Hive цена хранится целым количеством центов.
5. Добавить товар в избранное под Emma. Перезапустить приложение: пользователь, поля и лайк сохранятся.
6. Под Alex удалить этот товар с подтверждением. Он исчезнет из каталога и избранного всех пользователей.
7. Открыть `Hive`, выполнить проверку ключей. Показать фактический `HiveError: Wrong checksum in hive file. Box may be corrupted.` и последующее чтение контрольной строки правильным ключом.
8. Выполнить уплотнение рабочих боксов, затем отдельную демонстрацию. Она создаёт 100 редакций записи и 100 временных записей, удаляет временные и оставляет одну актуальную запись. На проверенном Android размер уменьшился **84 080 → 753 байта**.

Баннер и кнопка `Add to Cart` сохранены из исходного макета. Кнопка показывает локальный предварительный результат; заказ не сохраняется. Базовая цена соответствует Large, Medium = 90%, Small = 80%; затем учитывается количество. Задание по персональным данным закрывается избранным.

## Устройство хранения

Основные исходники:

- `lib/models.dart` — неизменяемые модели, ручные адаптеры и начальные товары. Стабильные `typeId`: пользователь 0, товар 1, избранное 2; поля имеют числовые идентификаторы.
- `lib/coffee_repository.dart` — инициализация Hive, ключ, вход/выход и сессия, проверки ролей, CRUD, избранное, демонстрации. Записи сериализованы в очередь, ошибки передаются интерфейсу.
- `lib/coffee_app.dart` — тема, исходные каталог и экран напитка, связанные с репозиторием через `ListenableBuilder`.
- `lib/auth_screens.dart` — форма входа, профиль и подтверждение выхода в существующей тёмной теме с кофейным акцентом.
- `lib/management_screens.dart` — формы, отдельное избранное, обслуживание Hive.
- `lib/main.dart` — получение приватного каталога, открытие хранилища и экран ошибки запуска.

Боксы: `users`, `products`, `favorites`, `settings`. Избранное содержит `userId` и `productId`, ключ пары уникален. Статус лайка не является общим полем товара: у разных пользователей он разный. Служебный признак `seeded` не позволяет заново заполнить каталог после удаления всех товаров. Удаление товара очищает связанные лайки; при запуске также удаляются осиротевшие ссылки.

Каталог Android: `/data/user/0/by.bstu.coffee_lab8/files/coffee_lab8/`. Основной ключ находится в `hive.key`, отдельно от файлов боксов. Ключ не включается в APK, исходники или журнал. Приватный файл выбран по условию лабораторной; дополнительная защита ключа через Keystore не используется. Hive шифрует значения; идентификаторы записей не следует считать секретными.

При отсутствующем, коротком или неправильном ключе существующая база не сбрасывается. Открытие выполняется с `crashRecovery: false`, чтобы неправильный ключ не привёл к восстановлению с усечением данных. Для продолжения нужно восстановить **исходный** `hive.key`; новый ключ не расшифрует старые данные.

Демонстрации используют отдельные зашифрованные боксы `key_demo` и `compact_demo`. `key_demo` закрывается перед каждой попыткой открытия, поскольку Hive игнорирует новый ключ для уже открытого бокса. В Hive 2.2.3 ошибка открытия также отправляется внутреннему completer; вспомогательная функция подписывается на оба результата через публичный API, поэтому ожидаемый отказ отображается без необработанного исключения.

Уплотнение освобождает место от старых версий и удалённых записей, сохраняя текущие значения. Это не ZIP-сжатие: если лишних записей нет, размер может не измениться.

## Зависимости и проверка

Runtime: Flutter, `hive: 2.2.3`, `path_provider`, `crypto` (отпечатки демопаролей). Генератор кода, библиотеки управления состоянием и роутер не нужны. `path_provider_android` закреплён на 2.2.23: ветка 2.3.x добавляет JNI и требует отсутствующий здесь Android SDK 35. Android-плагины приложения и Flutter используют согласованные AGP 9.1.0 / Kotlin 2.4.0; глобальные файлы SDK и пакетов не изменялись.

```powershell
flutter analyze
flutter test --reporter expanded
flutter build apk --debug
python tools/check-source.py
# При работающем Android-устройстве и настроенном окружении SDK/Gradle:
flutter drive --driver=test_driver/integration_test.dart --target=integration_test/lab8_test.dart -d emulator-5554
```

Интеграционный сценарий работает с отдельным временным каталогом и удаляет только собственные тестовые данные. Снимки сохраняются в `docs/screenshots`, результаты — в `docs/android-results.json`.
