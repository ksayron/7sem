## Границы проверки

- Пункт 7 выполнен по согласованному выбору через **battery_plus**: две реализации платформенного API внутри плагина общего канала, а не два самостоятельно созданных канала батареи.
- iOS-проект, iOS-сборка и запуск на iOS не выполнялись. Сравнение основано на документации и исходниках используемого battery_plus 7.1.2; iOS-реализация плагина написана на Objective-C.
- Физический Android-телефон не использовался; изображения камеры проверяются на эмуляторе.
- Возможность восстановления после уничтожения Activity реализована через `retrieveLostData`; widget-тест проверяет отображение восстановленного результата. Принудительное уничтожение процесса во время съёмки на устройстве не проверялось.
- Постоянное хранение фото, сервер, оплата и гарантированное срабатывание будильника не входят в лабораторную.

## Особенности сборки

В `lab6` сохранены настройки SDK/Gradle предыдущего проекта. Дополнительно согласованы инструменты test-плагина Flutter с приложением, отключён Kotlin incremental-кеш между дисками C:/D: и ограничена параллельность для сборки вместе с AVD. Общий Flutter SDK, исходники плагинов и проект `lab4-5` не редактировались. Есть предупреждение JVM native access; успешность подтверждается завершением команды, а не отсутствием предупреждений.

Сохранённое графическое состояние AVD давало полностью чёрные снимки; режим host GPU выдавал `Failed to allocate ColorBuffer with Vulkan backing`. Финальная проверка камеры и часов выполнена после холодного запуска с `-gpu swiftshader -feature -Vulkan -memory 1536 -cores 2 -no-window -no-snapshot-load -no-snapshot-save`. Runtime-параметры не меняют постоянный config.ini и userdata. В скрипте запуска применяются те же параметры рендеринга и памяти, с обычным окном эмулятора.
