# Flutter с нуля: подробный разбор лабораторной № 4–5

Этот гайд объясняет, как сверстать два экрана магазина кофе из нашего макета и как устроено уже готовое приложение в `PMP/lab4-5`. Он рассчитан на человека, который раньше не работал с Flutter. Начинать с изучения всего языка Dart не требуется: нужные конструкции разобраны по ходу.

**Результат:** ты понимаешь, какой кусок кода рисует каждый блок, умеешь менять расположение, размеры, отступы, цвета и картинки, можешь объяснить работу на защите и собрать похожий экран самостоятельно.

Здесь есть три вида кода:

- **Код проекта** — существующая реализация из `lib/coffee_app.dart`. Находи её через поиск в редакторе.
- **Учебный пример** — небольшой фрагмент для объяснения. Его не нужно бездумно вставлять посреди основного файла.
- **Упражнение** — изменение, которое можно попробовать и затем отменить.

Рабочие экраны уже готовы. Для первых опытов есть отдельный файл `examples/layout_practice.dart`; его запуск не меняет обычную точку входа приложения.

**Как читать:** первый проход — разделы 1–5 и упражнения 23.2. Затем изучай каталог по разделам 8–14, детали по разделам 15–20 и поведение по разделам 21–22. Разделы 24–28 используй как справочник. Все 28 разделов не требуется освоить за один присест.

## 1. Запускаем проект и учимся видеть изменения

### 1.1. Что здесь за технологии

**Flutter** — набор инструментов для создания интерфейсов и приложений. **Dart** — язык, на котором написан код. **Android Studio** — редактор и среда разработки. **Android-эмулятор** — виртуальный телефон, на котором запускается приложение.

Для этой лабораторной работаем с Android. В эмуляторе будет обычное мобильное приложение: его можно открыть, нажимать кнопки, вводить текст и возвращаться назад.

### 1.2. Самый простой запуск на этом компьютере

Открой PowerShell и выполни:

```powershell
cd D:\BSTU\7sem\PMP\lab4-5
.\tools\run-android.ps1
```

`cd` переводит терминал в папку проекта. Вторая команда запускает подготовленный скрипт. Он использует Android SDK и кеш Gradle на диске D, выбирает подключённый Android-эмулятор, а при необходимости запускает `coffee_lab`.

Дождись загрузки виртуального телефона и появления приложения. Первый запуск может занимать заметно больше времени: собирается Android-приложение и загружаются зависимости. Пока терминал продолжает сборку, повторно запускать ту же команду не нужно.

Если эмуляторов несколько:

```powershell
.\tools\run-android.ps1 -DeviceId emulator-5554
```

Идентификатор можно проверить командой:

```powershell
flutter devices
```

`emulator-5554` — пример идентификатора текущего эмулятора; после изменения порядка запуска номер может отличаться.

### 1.3. Запуск из Android Studio

1. Открой Android Studio.
2. Нажми **Open** и выбери `D:\BSTU\7sem\PMP\lab4-5`.
3. Открывай папку, в которой находится `pubspec.yaml`. Если открыть только `android`, работать с Flutter-проектом будет неудобно.
4. Если редактор не распознаёт Dart, проверь установку плагинов **Flutter** и **Dart** в настройках Plugins.
5. Для Flutter SDK укажи `D:\Soft\Flutter\flutter`, если редактор просит путь.
6. В Device Manager запусти `coffee_lab`.
7. Открой `lib/main.dart` и запусти Flutter-конфигурацию для этого файла. При отсутствии конфигурации используй действие Run рядом с `main` или создай конфигурацию типа Flutter с этой точкой входа.
8. В списке устройств выбери Android-эмулятор.

Названия и расположение меню могут немного различаться между версиями Android Studio. Запуск через PowerShell выше остаётся основным подготовленным способом на этом компьютере.

### 1.4. Как менять код без долгой пересборки

Пока `flutter run` работает в терминале:

| Действие | Что сделать | Для чего |
|---|---|---|
| Сохранить файл | `Ctrl+S` | Изменения должны попасть на диск |
| Hot reload | Нажать `r` в терминале запуска | Быстро показать изменения вёрстки |
| Hot restart | Нажать большую `R` | Перезапустить Dart-приложение и сбросить состояние |
| Завершить сеанс | Нажать `q` | Остановить запуск через Flutter |

Клавиши `r` и `R` вводятся в терминале, который сейчас выполняет `flutter run`, без команды `flutter r`. В Android Studio соответствуют действия **Hot Reload** и **Hot Restart**.

Hot reload обычно подходит для отступов, размеров и цветов. Он сохраняет текущее состояние: открытый экран, выбранную категорию, количество напитков. Если изменить начальное значение `_quantity = 1`, уже существующий счётчик после hot reload может остаться прежним. Для проверки нового начального значения нужен hot restart. Изменения Android-настроек требуют остановки и нового запуска. Подробнее: [официальное объяснение hot reload](https://docs.flutter.dev/tools/hot-reload).

### 1.5. Первый безопасный опыт

В `lib/coffee_app.dart` найди:

```dart
const coffeeOrange = Color(0xFFC78050);
```

Временно замени цвет:

```dart
const coffeeOrange = Color(0xFFB96F40);
```

Сохрани файл, сделай hot reload, посмотри на кнопки и выбранную категорию. Затем верни исходное значение. Это проверяет весь рабочий цикл: **нашёл код → изменил → сохранил → увидел результат → отменил**.

### 1.6. Учебный экран для экспериментов

Для него используется отдельная точка входа:


Запускай её после завершения предыдущего `flutter run`. Если идентификатор устройства другой, подставь его из `flutter devices`. Эмулятор уже должен быть запущен; для полной лабораторной используй подготовленный скрипт.

Учебный экран содержит заголовок, картинку, цену и кнопку-счётчик. В нём легко проверить действие `Padding`, `Row`, `Column`, `Expanded` и `setState`, не разбирая сразу большой файл.

Чтобы вернуться к лабораторной, заверши учебный запуск и снова выполни `.\tools\run-android.ps1`. Обычная точка входа остаётся `lib/main.dart`.

## 3. Минимум Dart, необходимый для чтения вёрстки

### 3.1. Скобки и вложенность

```dart
Padding(
  padding: const EdgeInsets.all(18),
  child: Column(
    children: [
      const Text('Espresso'),
      const SizedBox(height: 12),
      Image.asset('assets/images/iced_coffee.png'),
    ],
  ),
)
```

Читай этот фрагмент изнутри наружу:

1. `Text` выводит название.
2. `SizedBox` оставляет пустое место высотой 12.
3. `Image.asset` показывает картинку.
4. `Column` ставит эти три элемента друг под другом.
5. `Padding` добавляет вокруг всей колонки пространство 18.

`()` — вызов функции или конструктора. `[]` здесь — список элементов. `{}` используется для тела функции, класса, а также для некоторых коллекций. `child:` и `padding:` — имена параметров. Запятые разделяют параметры и элементы списка.

Запятая после последнего параметра допустима. Она облегчает редактирование и форматирование многострочного кода.

### 3.2. `child` и `children`

`child` принимает один виджет:

```dart
Center(child: Text('Coffee'))
```

`children` принимает список виджетов:

```dart
Row(children: [Text('Coffee'), Icon(Icons.coffee)])
```

Если в `Padding` хочется положить три элемента, положи в его `child` один `Column`, а уже в `children` этой колонки — три элемента.

### 3.3. Переменные и типы

```dart
int quantity = 1;        // целое число
double cardWidth = 160;  // число с дробной частью
String name = 'Coffee'; // текст
bool favorite = false;  // true или false
```

`final` означает, что переменной нельзя присвоить другое значение после инициализации:

```dart
final name = 'Espresso';
```

`const` — значение, которое можно определить при компиляции. Для неизменяемых виджетов часто пишут:

```dart
const SizedBox(height: 12)
```

Если текст зависит от переменной счётчика, виджет с этим текстом нельзя объявить `const`:

```dart
Text('$quantity')
```

`final` у коллекции запрещает заменить саму коллекцию, но не всегда запрещает менять её содержимое. Поэтому `final _favorites = <String>{...}` в нашем приложении допускает добавление и удаление названий. Содержимое `const`-коллекции менять нельзя.

### 3.4. Списки, множества и словари

```dart
final sizes = ['Small', 'Medium', 'Large']; // List: порядок важен
final favorites = <String>{'Vanilla Latte'}; // Set: уникальные значения
final options = <String, bool>{'Extra Milk': true}; // Map: ключ → значение
```

Индексы начинаются с нуля: `sizes[0]` — Small, `sizes[1]` — Medium, `sizes[2]` — Large.

`<String>` и `<String, bool>` уточняют типы данных. В `Set<String>` лежат строки, в `Map<String, bool>` строке соответствует логическое значение.

### 3.5. Функции и обработчики нажатий

```dart
void sayHello() {
  print('Hello');
}
```

`void` — функция не возвращает полезного результата. Стрелка `=>` позволяет кратко записать функцию из одного выражения:

```dart
void sayHello() => print('Hello');
```

Обработчик передают кнопке для выполнения **после нажатия**:

```dart
onPressed: sayHello,
```

Или используют анонимную функцию:

```dart
onPressed: () {
  sayHello();
},
```

`onPressed: sayHello()` означает вызов во время построения интерфейса и обычно приводит к ошибке типа. Для действий с аргументами используй `onPressed: () => doSomething(argument)`.

### 3.6. Условие прямо в вёрстке

```dart
Icon(favorite ? Icons.favorite : Icons.favorite_border)
```

Это сокращение: если `favorite` равно `true`, показать закрашенное сердце, иначе контурное.

```dart
if (products.isEmpty)
  const Text('No coffee found'),
```

Такое `if` внутри списка виджетов добавляет элемент только при выполнении условия.

### 3.7. Строки с переменными

```dart
Text('$quantity')
Text('${coffee.name}: ${coffee.price}')
```

`$quantity` подставляет значение переменной. Для выражения используют `${...}`. Чтобы вывести сам символ доллара, его экранируют:

```dart
Text('\$${coffee.price}')
```

В результате цена 3 выглядит как `$3`.

### 3.8. Классы, `this`, `widget` и подчёркивание

```dart
class Coffee {
  const Coffee(this.name, this.asset, this.price, this.category);

  final String name;
  final String asset;
  final int price;
  final int category;
}
```

Класс объединяет данные одного напитка. Конструктор `Coffee(...)` создаёт объект, а `this.name` в параметрах конструктора записывает переданное название в его поле `name`.

В объекте `State` выражение `widget.coffee` обращается к данным соответствующего `StatefulWidget`. `this` относится к текущему объекту, `widget` — к виджету, за состоянием которого этот объект следит.

Имя `_CoffeeCard` или `_quantity` с подчёркиванием считается приватным **в пределах библиотеки Dart**, а не только своего класса. В нашем проекте это помогает отделить внутренние детали файла от публичных экранов.

### 3.9. Знаки `?`, `!` и асинхронность

`bool?` может содержать `true`, `false` или `null`. `null` означает отсутствие значения. Чтение из словаря `_options[label]` может вернуть `null`, если ключа нет.

В `_options[label]!` знак `!` утверждает, что значение существует. Если ключа действительно нет, будет ошибка. Здесь подписи выбираются из заранее известного набора ключей.

`object?.method()` вызывает метод только если объект существует. Так скрывается клавиатура:

```dart
FocusManager.instance.primaryFocus?.unfocus();
```

`async` и `await` нужны для действий, результат которых появится позднее. В нашем переходе `await Navigator...push(...)` ждёт возвращения с экрана напитка. Это ожидание не блокирует работу интерфейса.

## 4. Что такое виджет и дерево виджетов

Виджет — описание части интерфейса. Это может быть текст, кнопка, картинка, отступ, способ выравнивания или целый экран.

`Text` показывает текст. `Padding` сам не рисует текст или рамку: он выделяет место вокруг дочернего элемента. `Row` определяет горизонтальное расположение. Поэтому экран строится из вложенных маленьких описаний.

```text
Scaffold
└── SafeArea
    └── Padding
        └── Column
            ├── Text
            ├── SizedBox
            └── Row
                ├── Image
                └── Text
```

Это дерево виджетов. Родитель — элемент уровнем выше. Дочерний элемент — тот, который находится внутри него. Например, `Column` является родителем `Row` в этой схеме.

### 4.1. `StatelessWidget`

```dart
class MyTitle extends StatelessWidget {
  const MyTitle({super.key});

  @override
  Widget build(BuildContext context) {
    return const Text('Coffee');
  }
}
```

Метод `build` возвращает описание интерфейса. `BuildContext` связывает этот участок с деревом приложения; через него получают тему, навигацию и другие окружающие возможности.

`StatelessWidget` не хранит отдельное изменяемое состояние через `State`. Но он **может перестраиваться** и получать новые параметры от родителя. Наша `_CoffeeCard` — такой виджет: состояние избранного хранит каталог, а карточка получает `favorite: true` или `false`.

### 4.2. `StatefulWidget`

Когда экран хранит выбранную категорию, счётчик или флажки, нужны `StatefulWidget` и его `State`. Виджет хранит конфигурацию, объект `State` — изменяемые значения и метод `build`. Именно поэтому у каталога два класса: `CatalogScreen` и `_CatalogScreenState`.

Определение и жизненный цикл: [официальный API StatefulWidget](https://api.flutter.dev/flutter/widgets/StatefulWidget-class.html).

### 4.3. Зачем выносить блоки в отдельные классы

Рекламный баннер вынесен в `_OfferBanner`, карточка — в `_CoffeeCard`, круглая кнопка — в `_RoundButton`. Так можно:

- менять баннер в одном месте;
- создавать несколько карточек по одному шаблону;
- задавать круглой кнопке иконку, цвет и действие без копирования всей реализации.

Это похоже на форму для деталей: форма одна, передаваемые данные различаются.

## 5. Размеры, ограничения и выравнивание

Это основной раздел для понимания вёрстки. Большинство проблем с положением элементов связано с ним.

### 5.1. Значения в Flutter — логические пиксели

```dart
const SizedBox(height: 20)
```

Здесь 20 логических пикселей. На экране высокой плотности им соответствует больше физических пикселей. Поэтому ширина скриншота 1080 пикселей не означает, что в коде нужно писать `width: 1080`.

Для вычислений ориентируйся на логическую ширину доступного места. У телефонов она часто составляет несколько сотен единиц.

### 5.2. Родитель задаёт допустимый размер

Родитель сообщает ребёнку ограничения ширины и высоты. Ребёнок выбирает размер внутри этих ограничений. Затем родитель располагает его. Поэтому собственный `width: 100` не всегда гарантирует ширину 100: родитель может требовать другую ширину.

Пример:

```dart
SizedBox(
  width: 200,
  child: Container(width: 100, color: Colors.orange),
)
```

В такой конструкции непосредственному ребёнку передаётся требование ширины 200. Если нужно поместить узкий прямоугольник внутри широкой области, добавь промежуточное выравнивание:

```dart
SizedBox(
  width: 200,
  child: Align(
    alignment: Alignment.centerLeft,
    child: Container(width: 100, height: 40, color: Colors.orange),
  ),
)
```

Подробное правило размеров: [Understanding constraints](https://docs.flutter.dev/ui/layout/constraints).

### 5.3. `Row` и `Column`: две оси

| Виджет | Главная ось — `mainAxis` | Поперечная ось — `crossAxis` |
|---|---|---|
| `Row` | Слева направо | Сверху вниз |
| `Column` | Сверху вниз | Слева направо |

```dart
Column(
  crossAxisAlignment: CrossAxisAlignment.start,
  children: [Text('Espresso'), Text('Coffee')],
)
```

Для колонки `start` выравнивает элементы слева при обычном направлении текста. Если этого не написать, колонка по умолчанию центрирует детей по поперечной оси.

```dart
Row(
  mainAxisAlignment: MainAxisAlignment.spaceBetween,
  children: [Text('Categories'), Text('See all')],
)
```

`spaceBetween` распределяет оставшееся место между детьми. Для двух элементов получаются левый и правый края, если сама строка получила достаточную ширину.

Свойства и примеры: [Row](https://api.flutter.dev/flutter/widgets/Row-class.html), [Column](https://api.flutter.dev/flutter/widgets/Column-class.html).

### 5.4. `Expanded`, `Flexible`, `Spacer`

```dart
Row(
  children: [
    Expanded(child: Text('Очень длинное название напитка')),
    const SizedBox(width: 8),
    const Text('\$3'),
  ],
)
```

Цена и зазор занимают своё место, `Expanded` получает оставшуюся ширину для названия. Без него текст в `Row` может потребовать слишком много места.

`Expanded` заставляет ребёнка заполнить выделенную долю оставшегося места. `Flexible` позволяет ребёнку занять меньше выделенного места. `Spacer` — пустая гибкая область:

```dart
Row(
  children: [Text('Dhaka, BD'), Spacer(), Icon(Icons.notifications)],
)
```

`Expanded`, `Flexible` и `Spacer` используются в структуре `Row`, `Column` или `Flex`. Не вставляй `Expanded` непосредственно в `Stack` или `Wrap`. Отступ обычно располагается **внутри** `Expanded`: `Expanded(child: Padding(...))`.

Точное поведение: [Expanded](https://api.flutter.dev/flutter/widgets/Expanded-class.html), [Flexible](https://api.flutter.dev/flutter/widgets/Flexible-class.html).

### 5.5. Отступы: три разных задачи

```dart
Padding(
  padding: const EdgeInsets.all(18),
  child: Text('Coffee'),
)
```

`Padding` оставляет место вокруг ребёнка. `Container.padding` делает то же внутри контейнера. `Container.margin` оставляет место снаружи контейнера. `SizedBox(height: 12)` между элементами — явный вертикальный зазор.

```dart
EdgeInsets.all(18)                         // все стороны
EdgeInsets.symmetric(horizontal: 18)       // слева и справа
EdgeInsets.symmetric(vertical: 12)         // сверху и снизу
EdgeInsets.only(top: 8, bottom: 12)         // выбранные стороны
EdgeInsets.fromLTRB(18, 12, 18, 24)         // left, top, right, bottom
```

У `fromLTRB` порядок всегда **лево → верх → право → низ**. Частая ошибка — поменять верх и право местами.

### 5.6. Почему `Expanded` ломается внутри прокрутки

Вертикальная прокрутка позволяет содержимому быть выше видимой области. В направлении прокрутки ребёнок может получить неограниченную высоту. Если внутри такой колонки написать `Expanded`, он не сможет понять, сколько свободной высоты следует заполнить.

Проблемная схема:

```text
SingleChildScrollView
└── Column
    └── Expanded        ← требует конечную оставшуюся высоту
```

Решение зависит от задачи: убрать вертикальный `Expanded`, дать конкретному блоку высоту или изменить структуру прокрутки. Внутри горизонтального `Row` на том же экране `Expanded` может работать нормально: доступная **ширина** ограничена экраном.

В наших карточках `Expanded` вокруг картинки безопасен: сетка выделяет карточке конечную высоту. На экране деталей вертикальная колонка внутри прокрутки не содержит такого растяжения.

## 6. Цвета, тема и точка входа

### 6.1. Почему `main.dart` такой маленький

```dart
import 'coffee_app.dart' as app;

void main() => app.main();
```

Программа начинается с `main()`. Этот файл передаёт запуск функции из `coffee_app.dart`. `as app` даёт импорту имя, чтобы было понятно, чья функция вызывается.

В основном файле:

```dart
void main() {
  WidgetsFlutterBinding.ensureInitialized();
  SystemChrome.setPreferredOrientations([DeviceOrientation.portraitUp]);
  runApp(const CoffeeApp());
}
```

Здесь подготавливается взаимодействие с Flutter, запрашивается портретная ориентация и запускается корневой виджет. Настройка ориентации зависит также от платформы и типа устройства; проверка нашей лабораторной проводилась на телефонном Android-эмуляторе.

### 6.2. Общие цвета

```dart
const coffeeBlack = Color(0xFF111111);
const coffeeCard = Color(0xFF202020);
const coffeeOrange = Color(0xFFC78050);
const coffeeMuted = Color(0xFFAAAAAA);
```

Формат `0xAARRGGBB`: `AA` — непрозрачность, затем красный, зелёный и синий. `FF` в начале означает полностью непрозрачный цвет. Для привычного цвета `#C78050` запись во Flutter — `Color(0xFFC78050)`.

Изменение `coffeeOrange` меняет все места, где используется эта константа. Изменение отдельного `color:` внутри конкретного виджета влияет только на этот участок.

### 6.3. `MaterialApp` и `Scaffold`

`MaterialApp` задаёт верхний уровень приложения: тему, первоначальный экран и инфраструктуру Material-интерфейса. У нас `home: const CatalogScreen()` выбирает каталог первым экраном.

`Scaffold` — каркас конкретной страницы. Его `body` содержит основное содержимое, `bottomNavigationBar` — нижнее меню. Фон берётся из темы, если не указан отдельно.

```dart
ThemeData(
  brightness: Brightness.dark,
  scaffoldBackgroundColor: coffeeBlack,
  colorScheme: const ColorScheme.dark(
    primary: coffeeOrange,
    surface: coffeeCard,
  ),
)
```

Тема даёт общие значения по умолчанию, а явный `TextStyle` или стиль кнопки может их переопределить.

## 7. Картинки с Pinterest и локальные assets

В приложение включены готовые изображения с Pinterest. Ссылки на страницы и исходные файлы перечислены в [image-sources.md](image-sources.md). При запуске они читаются из пакета приложения, поэтому подключение к интернету для показа кофе не требуется.

### 7.1. Почему используется PNG с прозрачностью

На макете стакан стоит поверх цветного фона. Прозрачные области картинки позволяют видеть фон приложения вокруг кофе. Если подставить JPEG с белым прямоугольником, прямоугольник будет виден.

Расширение `.png` само по себе не гарантирует прозрачность. Изображение должно действительно иметь прозрачный фон. Нарисованная шахматная сетка на картинке тоже не является прозрачностью.

### 7.2. Подключение картинки

Сначала положи файл, например `new_coffee.png`, в `assets/images/`. Затем зарегистрируй его в `pubspec.yaml`:

```yaml
flutter:
  uses-material-design: true
  assets:
    - assets/images/iced_coffee.png
    - assets/images/coffee_cup.png
    - assets/images/espresso.png
    - assets/images/new_coffee.png
```

Если секция `flutter:` уже есть, допиши путь в существующий список. Вторую одноимённую секцию создавать не нужно. В YAML отступы значимы: используй пробелы, а не табуляцию.

После изменения списка:

```powershell
flutter pub get
```

Затем останови приложение и запусти снова, если новый asset не подхватился. Правила подключения: [официальное руководство по assets](https://docs.flutter.dev/ui/assets/assets-and-images).

Показ изображения:

```dart
Image.asset(
  'assets/images/new_coffee.png',
  width: 160,
  height: 180,
  fit: BoxFit.contain,
)
```

Это путь внутри проекта и пакета приложения. Абсолютный Windows-путь `D:\...` здесь не нужен.

### 7.3. Что делает `fit`

| Значение | Результат | Где удобно |
|---|---|---|
| `BoxFit.contain` | Картинка целиком помещается в область с сохранением пропорций | Стакан, чашка, товар |
| `BoxFit.cover` | Область заполняется; края изображения могут не попасть в неё | Фотография-фон |
| `BoxFit.fill` | Область заполняется с возможным искажением пропорций | Обычно нежелательно для кофе |

В наших изображениях используется `contain`, чтобы не обрезать стакан и брызги. Определения: [BoxFit](https://api.flutter.dev/flutter/painting/BoxFit.html).

Если картинка кажется маленькой при большом `width`, проверь прозрачные поля внутри самого PNG. Flutter масштабирует весь файл, включая пустые области. Иногда нужно обрезать лишние поля в графическом редакторе, а не увеличивать виджет до огромного размера.

### 7.4. Как картинка связана с напитком

```dart
Coffee('Espresso', 'assets/images/iced_coffee.png', 3, 1),
```

Параметры: название, путь изображения, цена, индекс категории. Карточка и экран деталей читают `coffee.asset`, поэтому смена пути в этой строке меняет картинку в обоих местах.

## 8. Каркас каталога и прокрутка

Сначала разложим макет на части:

```text
Каталог
├── Прокручиваемая область
│   ├── Меню + Dhaka, BD + уведомления
│   ├── Баннер
│   ├── Поиск + сортировка
│   ├── Categories + See all
│   ├── Категории
│   └── Сетка напитков
└── Закреплённая нижняя навигация
```

В коде структура такая:

```text
Scaffold
├── body: SafeArea(bottom: false)
│   └── CustomScrollView
│       ├── SliverPadding
│       │   └── SliverList.list       верхние блоки
│       └── SliverPadding
│           └── SliverGrid.builder    карточки
└── bottomNavigationBar: _bottomBar()
```

### 8.1. Для чего `SafeArea`

Он добавляет отступ от областей системного интерфейса — например, от строки состояния и выреза камеры. У каталога `bottom: false`, потому что нижнее меню отдельно учитывает нижнюю безопасную область.

Без такого учёта заголовок может оказаться под часами телефона. Определение и пример: [SafeArea](https://api.flutter.dev/flutter/widgets/SafeArea-class.html).

### 8.2. Что такое sliver

В `CustomScrollView` список `slivers:` содержит части прокручиваемой области специального типа. `SliverList` показывает последовательность элементов, `SliverGrid` — сетку. Они участвуют в одной общей прокрутке.

Обычный `Text` нельзя напрямую вставить в `slivers:`. Для одного обычного виджета нужен `SliverToBoxAdapter(child: Text(...))`. Для набора обычных блоков в нашем проекте используется `SliverList.list(children: [...])`.

`SliverPadding` — отступ для sliver. Его параметр называется `sliver:`, а у обычного `Padding` — `child:`.

### 8.3. Почему не две независимые прокрутки

Если сделать верхнюю часть отдельной прокруткой, а под ней отдельный прокручиваемый `GridView`, управлять экраном будет сложнее: каждый участок начнёт двигаться сам. У нас заголовок, баннер и карточки движутся в одной области.

Нижнее меню находится в другом слоте `Scaffold`, поэтому остаётся на месте.

### 8.4. Основные отступы

| Место | Значение в текущем коде |
|---|---:|
| Левый и правый край контента | 18 |
| Верхний отступ первой группы | 8 |
| Между заголовком и баннером | 26 |
| Между баннером и поиском | 22 |
| Между поиском и строкой Categories | 14 |
| Между категориями и карточками | 20 |

Условие лабораторной допускает небольшие отклонения цветов и отступов. Сначала сохраняй порядок и выравнивание блоков, после этого подбирай числа.

## 9. Верхняя строка каталога

Ищи `Widget _header`. Схема:

```text
Row
├── круглая кнопка меню
├── SizedBox(width: 12)
├── иконка местоположения
├── текст Dhaka, BD
├── Spacer
└── Stack: колокольчик + маленькая точка
```

`Spacer` занимает оставшуюся ширину и отодвигает уведомления вправо. Изменение `SizedBox(width: 12)` меняет расстояние после меню, а не положение всего заголовка.

### 9.1. Красная точка поверх колокольчика

Точка накладывается через `Stack`. Упрощённый пример:

```dart
Stack(
  children: [
    IconButton(
      onPressed: () {},
      icon: const Icon(Icons.notifications_none),
    ),
    const Positioned(
      right: 10,
      top: 7,
      child: CircleAvatar(radius: 3, backgroundColor: Colors.red),
    ),
  ],
)
```

Первым рисуется колокольчик, затем точка. `right` и `top` задают расстояния от краёв локального `Stack`, а не всего экрана. Меньшее `right` приближает точку к правому краю.

### 9.2. Общая круглая кнопка

Класс `_RoundButton` принимает:

```dart
_RoundButton(
  icon: Icons.tune,
  color: coffeeOrange,
  label: 'Sort by price',
  onTap: () => setState(() => _sortByPrice = !_sortByPrice),
)
```

Внутри он создаёт `SizedBox` заданного размера и `IconButton`. `label` используется как `tooltip` — подсказка и название действия. Этот общий класс применяется в нескольких местах, поэтому изменение его реализации может повлиять сразу на несколько кнопок.

Меню открывает нижнюю панель с информацией о кофейне. Уведомления показывают `SnackBar`. Для выполнения лабораторной полноценные отдельные страницы этих разделов не понадобились.

## 10. Рекламный баннер

Ищи `class _OfferBanner`. Баннер состоит из слоёв:

```text
ClipRRect: скругление 18
└── SizedBox: высота 182
    └── Stack
        ├── тёмный градиент на весь прямоугольник
        ├── изображение справа снизу
        └── текст и кнопка слева сверху
```

### 10.1. Почему здесь нужен `Stack`

Текст и изображение частично занимают одну область. Если разместить их только в `Row`, картинка и текст получат строго соседние прямоугольники. `Stack` позволяет наложение, как в макете.

В `Stack.children` более поздние элементы рисуются поверх более ранних. Поэтому текст находится после фоновых слоёв. Правила: [Stack](https://api.flutter.dev/flutter/widgets/Stack-class.html).

### 10.2. Скругление и обрезка

```dart
ClipRRect(
  borderRadius: BorderRadius.circular(18),
  child: SizedBox(
    height: 182,
    child: Stack(children: [/* слои */]),
  ),
)
```

`ClipRRect` обрезает потомков по прямоугольнику со скруглёнными углами. Просто задать `borderRadius` у фоновой декорации недостаточно, если нужно также обрезать выступающую картинку.

### 10.3. Положение изображения

```dart
Positioned(
  right: -12,
  bottom: -12,
  width: 176,
  height: 177,
  child: Image.asset(
    'assets/images/espresso.png',
    fit: BoxFit.contain,
  ),
)
```

Отрицательное расстояние сдвигает область изображения за край баннера. Выступающая часть обрезается. Это сделано для композиции, где чашка почти касается правого и нижнего краёв.

Чтобы сдвинуть картинку влево, увеличь `right`, например до `0` или `8`. Чтобы увеличить её, меняй `width` и `height`; после этого проверь, не перекрыла ли она надписи.

### 10.4. Разноцветная надпись

В проекте используется `Text.rich` с `TextSpan`: один кусочек строки оранжевый, другой белый.

```dart
Text.rich(
  TextSpan(
    children: [
      TextSpan(
        text: '20% ',
        style: TextStyle(color: coffeeOrange),
      ),
      TextSpan(text: 'OFF On All\nEspresso!'),
    ],
  ),
  style: TextStyle(fontSize: 26, height: 1.23),
)
```

`\n` — принудительный перенос строки. `height: 1.23` задаёт множитель высоты строки текста; это не высота всего баннера.

Слева текст ограничен через `Positioned(left: 12, top: 12, right: 80, ...)`, чтобы оставить пространство изображению. Правая граница текста особенно важна при замене надписи на более длинную.

### 10.5. Кнопка Order Now

Она имеет высоту 33 и оранжевый фон. Её callback приходит через параметр `onOrder`, а каталог передаёт действие открытия Espresso. Баннер знает, как выглядеть, а родитель знает, куда перейти.

## 11. Поиск и круглая кнопка справа

Ищи `coffee-search`. Внешняя структура:

```text
Row
├── Expanded
│   └── Container: высота 46, фон coffeeCard, скругление 30
│       └── TextField
│           ├── prefixIcon: поиск
│           └── suffixIcon: микрофон
├── SizedBox(width: 10)
└── _RoundButton: оранжевая сортировка, размер 46
```

### 11.1. Почему поле обёрнуто в `Expanded`

У правой кнопки фиксированная ширина 46, между ними зазор 10. Поле занимает остальное. Такая схема подходит для разных ширин телефона без ручного вычисления ширины поиска.

Если доступная ширина строки 357, поиск получает `357 − 46 − 10 = 301`.

### 11.2. Оформление поля

```dart
decoration: InputDecoration(
  border: InputBorder.none,
  hintText: 'Search coffee...',
  hintStyle: TextStyle(fontSize: 11, color: coffeeMuted),
  prefixIcon: Icon(Icons.search, color: coffeeMuted, size: 25),
)
```

`InputBorder.none` убирает стандартную рамку поля. Фон и внешнее скругление находятся у родительского контейнера. `hintText` — подсказка, видимая до ввода текста. `prefixIcon` — иконка слева, `suffixIcon` — элемент справа.

Размер введённого текста задаётся `TextField.style`, размер подсказки — `decoration.hintStyle`. Это два разных места.

### 11.3. Как работает поиск

```dart
onChanged: (value) => setState(() => _query = value),
```

При вводе обновляется строка `_query`. Затем `build` заново вычисляет список напитков:

```dart
coffee.name.toLowerCase().contains(_query.toLowerCase().trim())
```

Обе строки переводятся в нижний регистр, поэтому `ESPRESSO` и `espresso` подходят одинаково. `trim()` убирает пробелы по краям запроса, `contains()` ищет вхождение текста в название.

Поиск применяется к текущей категории или избранному. Если напиток не появляется, попробуй **See all** и убедись, что открыта вкладка Home.

### 11.4. Что делают две иконки

Оранжевая кнопка с ползунками включает и выключает сортировку по цене. В коде:

```dart
setState(() => _sortByPrice = !_sortByPrice)
```

А в `build`:

```dart
if (_sortByPrice) {
  products.sort((a, b) => a.price.compareTo(b.price));
}
```

Микрофон показывает подсказку о вводе названия. **Распознавание голоса здесь не реализовано.** Это важно при объяснении работы: наличие иконки ещё не означает наличие голосового сервиса.

## 12. Категории и их горизонтальная прокрутка

Ищи `Widget _categories`. Заголовок Categories и кнопка See all — отдельная строка над категориями. В ней `Spacer` прижимает кнопку к правому краю.

### 12.1. Горизонтальный список

```dart
SizedBox(

    separatorBuilder: (_, _) => const SizedBox(width: 10),
```

`Axis.horizontal` меняет направление прокрутки. `height: 36` даёт списку конечную высоту. `separatorBuilder` создаёт зазоры между соседями. Ширина каждой категории зависит от текста и внутренних отступов.

Если все категории не помещаются, их можно прокрутить вбок. Последнюю категорию не нужно силой сжимать до нечитаемого размера.

### 12.2. Индексы категорий

```dart
const labels = ['Hot Coffee', 'Iced Coffee', 'Frappuccino', 'Mocha'];
```

| Индекс | Категория |
|---:|---|
| 0 | Hot Coffee |
| 1 | Iced Coffee |
| 2 | Frappuccino |
| 3 | Mocha |

Индекс в `Coffee(..., category)` должен соответствовать этому порядку. Начальное `_category = 1` выбирает Iced Coffee.

### 12.3. Форма капсулы

```dart
Material(
  color: selected ? coffeeOrange : Colors.transparent,
  shape: StadiumBorder(
    side: BorderSide(
      color: selected ? coffeeOrange : const Color(0xFF484848),
    ),
  ),
  child: InkWell(
    customBorder: const StadiumBorder(),

```

`StadiumBorder` делает края округлыми, как у капсулы. `Material` задаёт поверхность и форму, `InkWell` обрабатывает касание и рисует эффект нажатия на Material-поверхности.

В выбранной категории оранжевый фон и белые элементы. В невыбранной — прозрачный фон, серая рамка и серые элементы. Оформление зависит от:

```dart
final selected = !_showAll && index == _category;
```

Когда включено See all, ни одна категория не выделена. При нажатии категории режим всех напитков выключается.

## 13. Сетка и карточка напитка

Здесь две отдельные задачи: сетка решает, **куда поставить карточки и сколько места им выделить**, а `_CoffeeCard` решает, **что находится внутри одной карточки**.

### 13.1. Настройка сетки

```dart
SliverGrid.builder(
  gridDelegate: const SliverGridDelegateWithFixedCrossAxisCount(
    crossAxisCount: 2,
    mainAxisSpacing: 18,
    crossAxisSpacing: 18,
    childAspectRatio: 0.74,
  ),
  itemCount: products.length,
  itemBuilder: (context, index) {
    final coffee = products[index];
    return _CoffeeCard(
      coffee: coffee,
      favorite: _favorites.contains(coffee.name),
      onFavorite: () => _favorite(coffee),
      onTap: () => _openCoffee(coffee),
    );
  },
)
```

| Параметр | Значение в вертикальной сетке |
|---|---|
| `crossAxisCount: 2` | Две колонки |
| `mainAxisSpacing: 18` | Вертикальный зазор между рядами |
| `crossAxisSpacing: 18` | Горизонтальный зазор между колонками |
| `childAspectRatio: 0.74` | Ширина карточки / высота карточки |
| `itemCount` | Сколько карточек построить |
| `itemBuilder` | Как создать карточку с заданным индексом |

У вертикальной сетки поперечная ось горизонтальна. Поэтому отношение `childAspectRatio` здесь — именно ширина к высоте. Официальное определение: [childAspectRatio](https://api.flutter.dev/flutter/rendering/SliverGridDelegateWithFixedCrossAxisCount/childAspectRatio.html).

### 13.2. Как посчитать размеры

Предположим, логическая ширина экрана — 393. Слева и справа по 18, между колонками 18:

```text
Ширина контента = 393 − 18 − 18 = 357
Ширина карточки = (357 − 18) / 2 = 169.5
Высота карточки = 169.5 / 0.74 ≈ 229.1
```

Если уменьшить отношение до `0.65`, карточка станет выше. Если увеличить до `0.85`, она станет ниже. Это часто воспринимается наоборот, поэтому запомни формулу **высота = ширина / отношение**.

Для вертикальной сетки из `n` колонок:

```text
cardWidth = (contentWidth − gap × (n − 1)) / n
cardHeight = cardWidth / childAspectRatio
```

### 13.3. Внутреннее устройство карточки

```text
Material: фон coffeeCard, скругление 10, обрезка
└── InkWell: открывает напиток
    └── Stack
        ├── Padding(12, 24, 12, 13)
        │   └── Column
        │       ├── Expanded: картинка
        │       ├── SizedBox(height: 12)
        │       └── Row: название + USD + цена
        └── Positioned(right: 4, top: 3): сердце
```

Картинка получает оставшуюся высоту после нижней строки и отступов. Это позволяет карточкам иметь одинаковый размер, даже когда сами файлы изображений имеют разные пропорции.

Сердце рисуется отдельным слоем, поэтому не отнимает высоту у картинки. Верхний внутренний отступ 24 оставляет место для него.

### 13.4. Название и цена

```dart
Row(
  children: [
    Expanded(
      child: Text(coffee.name, style: TextStyle(fontSize: 11)),
    ),
    Text('USD ', style: TextStyle(fontSize: 7, color: coffeeMuted)),
    Text('\$${coffee.price}', style: TextStyle(fontSize: 12)),
  ],
)
```

Второй `Expanded` в этой карточке работает по ширине: название занимает место до цены. Это отдельная задача от вертикального `Expanded` картинки.

Для очень длинных названий можно ограничить текст:

```dart
Text(
  coffee.name,
  maxLines: 1,
  overflow: TextOverflow.ellipsis,
  style: const TextStyle(fontSize: 11),
)
```

Но если макет допускает две строки, вместо обрезки выбери `maxLines: 2` и проверь высоту карточки.

### 13.5. Нажатие на карточку и на сердце

Вся карточка открывается через `InkWell.onTap`. У сердца свой `IconButton.onPressed`, который меняет избранное. Это два отдельных обработчика.

`Key('product-${coffee.name}')` помогает автоматическому тесту найти нужную карточку. Ключ не рисуется на экране и не управляет её размером.

## 15. Экран напитка: слои, фон и большое изображение

Ищи `class _CoffeeDetailsScreenState`. Этот экран выглядит сложным, но состоит из двух уровней наложения.

### 15.1. Общий `Stack` страницы

```text
Scaffold: чёрный фон
└── LayoutBuilder
    └── Stack
        ├── оранжевый верхний фон
        ├── чёрный фон с округлым верхом
        ├── SingleChildScrollView
        │   └── Column
        │       ├── верхний блок: надпись + стакан + кнопки
        │       └── название + опции + количество + размеры
        └── закреплённый блок цены и Add to Cart
```

Первые два слоя — фон. Третий слой — прокручиваемое содержимое. Последний — закреплённая панель покупки, которая находится поверх содержимого.

### 15.2. `LayoutBuilder` и высота верхнего блока

```dart
final heroHeight = (constraints.maxHeight * 0.46).clamp(
  300.0,
  390.0,
);
```

`LayoutBuilder` сообщает ограничения области, в которой строится его ребёнок. Здесь берётся 46% доступной высоты и ограничивается диапазоном 300–390.

Примеры:

| Доступная высота | 46% | Итоговая `heroHeight` |
|---:|---:|---:|
| 600 | 276 | 300 — сработала нижняя граница |
| 750 | 345 | 345 |
| 900 | 414 | 390 — сработала верхняя граница |

Это высота области верхней композиции, а не точная высота непрозрачной части стакана. Файл ещё масштабируется через `BoxFit.contain`.

Здесь используется размер доступного `body`, который может отличаться от полного размера дисплея. `LayoutBuilder` удобен именно для решений по размеру родительской области.

### 15.3. Два фоновых слоя

```dart
Positioned(
  top: 0,
  left: 0,
  right: 0,
  height: heroHeight,
  child: const ColoredBox(color: coffeeOrange),
),
Positioned.fill(
  top: heroHeight * 0.61,
  child: const DecoratedBox(
    decoration: BoxDecoration(
      color: coffeeBlack,
      borderRadius: BorderRadius.vertical(
        top: Radius.circular(46),
      ),
    ),
  ),
),
```

Чёрный слой начинается примерно на 61% высоты верхнего блока. Если `heroHeight = 350`, его верх находится на `350 × 0.61 = 213.5`. Стакан находится поверх обоих фонов и визуально пересекает их границу.

`Positioned.fill` привязывает ребёнка к краям `Stack`, а заданный `top` смещает верхнюю границу. У чёрного блока скруглены только верхние углы. Нижние углы относятся к форме экрана телефона, а не к карточке внутри Flutter.

Изменишь `0.61` на `0.70` — чёрная область начнётся ниже. Уменьшишь до `0.50` — поднимется выше. Размер картинки от этого сам по себе не изменится.

### 15.4. Внутренний `Stack` верхнего блока

```text
SizedBox(height: heroHeight)
└── Stack
    ├── Positioned: полупрозрачный Iced Coffee
    ├── Positioned: большая картинка
    └── Positioned: строка назад + сердце
```

Надпись находится за картинкой. Кнопки находятся поверх неё. Если поменять порядок детей, результат наложения изменится.

### 15.5. Почему добавляется `topInset`

```dart
final topInset = MediaQuery.paddingOf(context).top;
```

Этот экран не обёрнут целиком в верхний `SafeArea`: фон должен продолжаться за системной строкой состояния. Поэтому отступ для кнопок и изображения учитывается вручную:

```dart
top: topInset + 8,
```

Так фон занимает верх экрана, а кнопки остаются ниже системных значков. Не добавляй поверх этого ещё один верхний `SafeArea` без пересмотра координат: можно получить двойной отступ.

### 15.6. Надпись за стаканом

```dart
FittedBox(
  child: Text(
    'Iced Coffee',
    style: TextStyle(
      fontSize: 70,
      fontWeight: FontWeight.w800,
      color: Colors.white.withValues(alpha: 0.27),
    ),
  ),
)
```

`FittedBox` масштабирует содержимое под доступную область. Поэтому реальная величина букв зависит и от ширины строки: одно увеличение `fontSize` внутри такого `FittedBox` не всегда заметно увеличит итоговую надпись.

`alpha: 0.27` — прозрачность цвета: 0 полностью прозрачно, 1 полностью непрозрачно. Именно прозрачность делает надпись фоновым декоративным элементом.

### 15.7. Большая картинка

```dart
Positioned(
  left: 28,
  right: 28,
  top: topInset + 8,
  bottom: 0,
  child: Image.asset(widget.coffee.asset, fit: BoxFit.contain),
)
```

Заданные левая и правая границы определяют доступную ширину; верх и низ — высоту. Чтобы дать изображению больше ширины, уменьши `left` и `right`. Чтобы изменить общий вертикальный размер композиции, меняй `heroHeight`.

Область изображения и сам видимый стакан — разные вещи: пропорции и прозрачные поля PNG влияют на итоговый результат.

### 15.8. Системные панели Android

Часы, сеть, батарея и нижняя область жестов относятся к Android. В Flutter мы задаём пожелания к их оформлению через `AnnotatedRegion<SystemUiOverlayStyle>` и рисуем подходящий фон под ними.

В деталях базовый фон `Scaffold` чёрный, а оранжевый фон — только отдельный верхний слой. Это сохраняет чёрный фон у нижнего края. Поведение системных цветов зависит от версии Android и режима edge-to-edge, поэтому после изменений проверяй **сам эмулятор**.

Не нужно рисовать в Flutter фальшивые часы и батарею только для копирования iPhone из макета. У лабораторной целевое устройство — Android-эмулятор.

## 16. Название, рейтинг и текст

После верхней картинки идёт группа с отступами `EdgeInsets.fromLTRB(18, 12, 18, 0)`. Внутри первая строка:

Название получает оставшуюся ширину, рейтинг занимает место справа. Если название длинное, оно может переноситься внутри своего `Expanded`. Прежде чем увеличивать шрифт, проверяй, осталось ли место рейтингу.

### 16.1. Основные свойства текста


|---|---|

## 17. Опции и перенос элементов через Wrap

В макете слева находятся Customizations и Add-Ons, справа — счётчик. В коде их объединяет `Row(crossAxisAlignment: CrossAxisAlignment.start)`:

```text
Row
├── Expanded
│   └── Column: заголовки и опции
├── SizedBox(width: 8)
└── Column: минус, количество, плюс
```

`crossAxisAlignment.start` выравнивает верх этих двух колонок. Левая получает оставшуюся ширину, правая — ширину своих кнопок.

### 17.1. Почему опции сделаны через `Wrap`

```dart
Wrap(
  spacing: 12,
  runSpacing: 4,
  children: ['Extra Milk', 'Less Sugar', 'Add Flavor']
      .map(_option)
      .toList(),
)
```

`Row` пытается оставить детей на одной линии. `Wrap` переносит не поместившиеся элементы на следующую. `spacing` — горизонтальный зазор между соседями, `runSpacing` — зазор между строками.

На широком телефоне три опции могут оказаться в одном ряду, на узком — в двух. Это нормальная адаптация; обязательный порядок сохраняется.

`.map(_option)` превращает каждую строку в виджет, вызывая нашу функцию `_option`. `.toList()` собирает полученные виджеты в список.

### 17.2. Устройство одной опции

```text
Semantics: сообщает состояние checked
└── InkWell: обрабатывает касание
    └── Padding(vertical: 4)
        └── Row(mainAxisSize: min)
            ├── иконка чекбокса
            ├── зазор 4
            └── текст
```

`mainAxisSize: MainAxisSize.min` позволяет опции быть по ширине своего текста, вместо занятия всей строки. Это важно для размещения нескольких опций в `Wrap`.

### 17.3. Это рисованные чекбоксы

Вместо стандартного `Checkbox` использованы `Icon` и `InkWell`, чтобы получить компактный размер макета. При нажатии изменяется значение словаря:

```dart
onTap: () => setState(() => _options[label] = !_options[label]!),
```

Иконка выбирается по значению:

```dart
_options[label]!
    ? Icons.check_box_outlined
    : Icons.check_box_outline_blank
```

`Semantics` сообщает вспомогательным технологиям, что элемент отмечен или снят. Сам `Semantics` не рисует рамку и не меняет размеры.

Опции в текущей лабораторной изменяют своё выделение. На цену они не влияют.

## 18. Счётчик количества

Ищи `Decrease quantity` или `Increase quantity`.

```dart
int _quantity = 1;
```

Это начальное состояние. Кнопки расположены вертикально, как в макете:

```text
минус: круглая кнопка 34 × 34
количество: Text, верхний и нижний отступ 10
плюс: круглая кнопка 34 × 34
```

Уменьшение:

```dart
onTap: () {
  if (_quantity > 1) {
    setState(() => _quantity--);
  }
},
```

Увеличение:

```dart
onTap: () => setState(() => _quantity++),
```

`++` прибавляет единицу, `--` вычитает единицу. Проверка `> 1` сохраняет минимум 1. При нажатии минуса на единице ничего не меняется.

Чтобы добавить верхний предел, например 9, можно заменить обработчик плюса:

```dart
onTap: () {
  if (_quantity < 9) {
    setState(() => _quantity++);
  }
},
```

Это учебное изменение: в текущем проекте такого максимума нет. После изменения проверь оба граничных значения.

## 19. Выбор размера напитка

Ищи `const sizes = ['Small', 'Medium', 'Large']`.

Начальный индекс 2 означает Large. Три варианта строятся через `List.generate(3, ...)`, каждый находится в `Expanded`, поэтому имеет одинаковую долю ширины строки.

### 19.1. Разные размеры одной картинки

```dart

```

Получаются высоты 44, 53 и 62. Используется один и тот же PNG, который масштабируется. Отдельные файлы для Small, Medium и Large не требуются.

### 19.2. Выбор и рамка

```dart
onTap: () => setState(() => _size = index),
```

```dart
border: Border.all(
```

## 20. Цена и закреплённая кнопка Add to Cart

Это последний ребёнок внешнего `Stack`, поэтому панель рисуется поверх прокручиваемой части.

### 20.1. Фиксация к низу

```dart
Positioned(
  bottom: 0,
  left: 0,
  right: 0,
  child: Container(
    color: coffeeBlack,
    child: SafeArea(
      top: false,
      child: Padding(
        padding: const EdgeInsets.fromLTRB(18, 18, 18, 24),
        child: Row(/* цена и кнопка */),
      ),
    ),
  ),
)
```

`bottom: 0` прижимает панель к нижнему краю `Stack`. `left: 0` и `right: 0` дают ей всю ширину. Собственная высота определяется содержимым и отступами.

`SafeArea(top: false)` учитывает нижнюю системную область. Чёрный контейнер расположен снаружи безопасного отступа, поэтому фон продолжается до самого края.

### 20.2. Почему низ прокрутки имеет дополнительный отступ

```dart
padding: EdgeInsets.only(
  bottom: 120 + MediaQuery.paddingOf(context).bottom,
),
```

Панель лежит поверх прокрутки, а не занимает отдельное место внутри её колонки. Без этого нижние размеры напитка могли бы оказаться под кнопкой, и прокрутить их выше было бы невозможно.

120 — запас для текущего размера панели. Если увеличишь панель или существенно увеличишь текст, пересмотри этот запас. Это конкретное решение для нашей композиции, а не универсальная высота всех нижних панелей.

### 20.3. Строка покупки

```text
Row
├── новая цена, размер текста 34
├── зазор 8
├── старая цена, размер 16, зачёркнута
├── зазор 25
└── Expanded
    └── SizedBox(height: 50)
        └── FilledButton.icon: Add to Cart
```

Кнопка заполняет остаток ширины. На узком телефоне она становится уже. Если добавишь длинную надпись или большую цену, уменьши лишние зазоры либо пересмотри строку — например, размести две цены вертикально.

### 20.4. Как считается цена в этой лабораторной

```dart
final price =
    (widget.coffee.price - 1 + (_size == 0 ? -0.5 : 0)) * _quantity;
```

Это демонстрационная формула для воспроизведения цены в макете. Она не является системой расчёта реального магазина.

Для Espresso в каталоге указано 3:

| Выбор | Расчёт за одну порцию | Итог при количестве 1 |
|---|---|---:|
| Large | `3 − 1` | $2 |
| Medium | `3 − 1` | $2 |
| Small | `3 − 1 − 0.5` | $1.50 |

При двух Small итог `$3`. Старая цена показывается как `price × 1.25`, то есть для `$2` это `$2.50`. Изменённые флажки молока и сахара в формулу не входят.

Если хочешь другую систему цен, меняй формулу осознанно и обновляй ожидаемые результаты тестов, которые проверяют прежний расчёт.

### 20.5. Форматирование и зачёркивание

Для целого итога показывается `$2`, для дробного — `$1.50`. В коде проверяется равенство округлённому значению, затем выбирается `toInt()` или `toStringAsFixed(2)`.

Старая цена зачёркивается через:

```dart
decoration: TextDecoration.lineThrough,
```

### 20.6. Действие Add to Cart

Кнопка показывает `SnackBar`, например `2 × Espresso added to cart`. Список корзины, сервер, оформление заказа и оплата в этой лабораторной не реализованы.

Функция `coffeeMessage` сначала скрывает предыдущее сообщение и затем показывает новое. Две точки `..` — каскадная запись Dart: несколько методов вызываются у одного объекта `ScaffoldMessenger`.

## 21. Состояние: почему интерфейс реагирует на нажатия

До этого мы разбирали размещение элементов. Теперь соединим данные и внешний вид.

### 21.1. Минимальный рабочий пример

```dart
class CounterExample extends StatefulWidget {
  const CounterExample({super.key});

  @override
  State<CounterExample> createState() => _CounterExampleState();
}

class _CounterExampleState extends State<CounterExample> {
  int count = 1;

  @override
  Widget build(BuildContext context) {
    return Column(
      mainAxisSize: MainAxisSize.min,
      children: [
        Text('$count'),
        FilledButton(
          onPressed: () {
            setState(() {
              count++;
            });
          },
          child: const Text('Добавить'),
        ),
      ],
    );
  }
}
```

Цепочка:

```text
Нажатие → изменение count в setState → планируется build
→ новый Text получает новое count → экран обновляется
```

`setState` выполняет переданную функцию синхронно и сообщает Flutter, что нужно перестроить соответствующую часть интерфейса. Не помещай `async`-операцию в callback самого `setState`. Подробности: [State.setState](https://api.flutter.dev/flutter/widgets/State/setState.html).

### 21.2. Почему переменные находятся перед `build`

Правильно:

```dart
class _ExampleState extends State<Example> {
  int count = 1;

  @override
  Widget build(BuildContext context) {
    // Используем count.
  }
}
```

Если каждый раз внутри `build` создавать `int count = 1`, новое построение будет снова начинать с единицы. Поле объекта `State` живёт между перестроениями.

Зато производные значения — отфильтрованный список `products` и рассчитанная цена `price` — удобно вычислять в `build` из текущего состояния.

### 21.3. Состояние нашего каталога

| Поле | Что хранит |
|---|---|
| `_favorites` | Множество названий избранных напитков |
| `_category` | Индекс выбранной категории |
| `_tab` | Home или Favorite |
| `_query` | Текст поиска |
| `_showAll` | Показать все категории |
| `_sortByPrice` | Сортировать цены по возрастанию |

Сердце меняет множество:

```dart
void _favorite(Coffee coffee) => setState(() {
  if (!_favorites.add(coffee.name)) {
    _favorites.remove(coffee.name);
  }
});
```

`Set.add` возвращает `true`, если значение добавилось. Если оно уже было в множестве, возвращается `false`, и название удаляется. Это переключатель «добавить / убрать».

Использование названия как идентификатора достаточно для нашего небольшого учебного списка. Для реального каталога обычно вводят отдельный уникальный ID.

### 21.4. Состояние экрана напитка

| Поле | Что хранит |
|---|---|
| `_quantity` | Количество |
| `_size` | Small, Medium или Large по индексу |
| `_favorite` | Локальное состояние сердца |
| `_options` | Какие флажки включены |

`late bool _favorite = widget.favorite` получает начальное значение от каталога. При нажатии сердца вызывается родительский `widget.onFavorite()`, а затем обновляется локальный флаг. Так сердце на странице напитка и состояние каталога согласованы.

### 21.5. Что сохраняется при возвращении и при перезапуске

Каталог остаётся в стеке навигации, пока открыт напиток. После возвращения его избранное и поиск остаются. При повторном открытии деталей создаётся новая страница, количество снова 1, размер Large, опции включены.

После полного перезапуска приложения всё состояние восстанавливается из начальных значений кода. Хранение в файле или базе данных здесь не используется. Hot reload обычно сохраняет уже существующее состояние, поэтому для проверки начальных значений используй hot restart.

## 22. Переход между экранами

Ищи `Future<void> _openCoffee`.

```dart
await Navigator.of(context).push(
  MaterialPageRoute<void>(
    builder: (_) => CoffeeDetailsScreen(
      coffee: coffee,
      favorite: _favorites.contains(coffee.name),
      onFavorite: () => _favorite(coffee),
    ),
  ),
);
```

`Navigator` управляет стеком страниц. `push` добавляет новую страницу сверху, `pop` удаляет верхнюю и возвращает предыдущую.

```text
Сначала:          [Каталог]
Открыли Espresso: [Каталог, Детали Espresso]
Нажали назад:    [Каталог]
```

`MaterialPageRoute` описывает страницу и её переход. `builder` создаёт экран напитка. `_` здесь означает, что параметр контекста этой функции нам не нужен.

Назад:

```dart
onTap: () => Navigator.pop(context),
```

Перед переходом скрывается клавиатура через `unfocus()`. После возвращения проверяется:

```dart
if (mounted) setState(() {});
```

`mounted` показывает, что объект состояния всё ещё связан с деревом интерфейса. Проверка нужна перед обновлением после `await`, потому что к моменту завершения ожидания экран теоретически мог быть удалён. Пустое обновление здесь инициирует повторное построение каталога после возврата.

По условию лабораторной можно показывать страницы даже без переходов. Наш проект уже содержит переходы, поэтому для демонстрации достаточно нажать Espresso, Order Now или Custom.


Проверяй каждое действие сразу после реализации. Если одновременно изменить вёрстку, формулу цены и навигацию, найти причину проблемы будет сложнее.

### 23.15. Доведи соответствие макету

Сравнивай экран по уровням:

1. **Большие области:** фон, высота баннера, верх деталей, нижние панели.
2. **Структура:** порядок элементов, две колонки, размещение кнопок.
3. **Отступы:** края, расстояния между блоками.
4. **Типографика:** размер заголовков и мелкого текста.
5. **Детали:** оттенки, рамки, прозрачность, иконки.

Сначала исправь смещённую сетку, затем подбирай оттенок маленькой иконки. Так каждая правка решает заметную задачу.

## 24. Готовые рецепты изменений

Это справочник «хочу изменить X — где искать». Вноси изменения по одному и делай hot reload.

### 24.1. Сдвинуть весь контент каталога от краёв

Ищи оба `SliverPadding` в каталоге. У первого:

```dart
padding: const EdgeInsets.fromLTRB(18, 8, 18, 0),
```

У сетки:

```dart
padding: const EdgeInsets.fromLTRB(18, 0, 18, 20),
```

Меняй левые и правые 18 согласованно, например на 22. Если изменить только верхнюю группу, края баннера и карточек перестанут совпадать.

### 24.2. Сделать карточки выше

В делегате сетки:

```dart
childAspectRatio: 0.68,
```

Меньшее отношение даёт большую высоту. Не начинай с установки случайной `height` у внутренней карточки: размер ей уже назначает сетка.

### 24.3. Сделать расстояния между карточками меньше

```dart
mainAxisSpacing: 12,
crossAxisSpacing: 12,
```

Карточки станут шире при том же количестве колонок. Это также изменит их высоту, поскольку она вычисляется из отношения сторон.

### 24.4. Увеличить изображение внутри карточки

Ищи `EdgeInsets.fromLTRB(12, 24, 12, 13)` в `_CoffeeCard`. Уменьшение боковых отступов даёт картинке больше ширины. Уменьшение вертикальных отступов даёт больше высоты. Сначала проверь прозрачные поля изображения.

Не убирай весь верхний отступ без проверки: изображение может столкнуться с сердцем.

### 24.5. Увеличить скругление

| Блок | Где менять |
|---|---|
| Баннер | `ClipRRect` → `BorderRadius.circular(18)` |
| Карточка | `Material` → `BorderRadius.circular(10)` |
| Поиск | `BoxDecoration` → `BorderRadius.circular(30)` |
| Чёрный верх деталей | `Radius.circular(46)` |
| Рамка выбранного размера | `BorderRadius.circular(7)` |

Если один блок задаёт и рисунок рамки, и область эффекта нажатия, желательно сохранить одинаковое скругление в обоих местах.

### 24.6. Изменить город

Ищи строку `Dhaka, BD`. Замени на `Minsk, BY`. Это текст, а не подключённая геолокация.

После замены проверь, помещается ли строка вместе с иконкой местоположения и уведомлениями.

### 24.7. Добавить напиток

Добавь строку в `const coffees`:

```dart
Coffee('Hazelnut Latte', 'assets/images/coffee_cup.png', 4, 1),
```

Он появится в Iced Coffee, потому что индекс категории 1. Для новой картинки сначала выполни подключение assets из раздела 7.

Название желательно сделать уникальным: оно используется для избранного и ключа карточки.

### 24.8. Заменить картинку только у одного напитка

Меняй путь в его строке `Coffee(...)`, а не общий `Image.asset(coffee.asset)` в карточке. Общий код должен продолжать получать разные данные.

### 24.9. Изменить стартовую категорию или размер

```dart
int _category = 0; // Hot Coffee
```

```dart
int _size = 1; // Medium
```

Нужен **hot restart**, поскольку изменились начальные значения существующего состояния.

### 24.10. Добавить ещё одну опцию

Сначала добавь её в словарь:

```dart
'Cinnamon': false,
```

Затем добавь `'Cinnamon'` в соответствующий список перед `.map(_option)`. Если добавить только подпись, `_options[label]!` получит отсутствующее значение и возникнет ошибка.

Проверь перенос `Wrap`: дополнительная опция может увеличить высоту блока.

### 24.11. Сделать кнопку покупки выше

Ищи `SizedBox(height: 50)` рядом с `add-to-cart`. Например, замени на 56. Проверь нижний запас прокрутки и доступность размеров.

Если менять общий `_RoundButton.size`, это не влияет на Add to Cart: она построена другим виджетом.

### 24.12. Перевести надписи на русский

Меняй пользовательские строки: Categories → Категории, Add to Cart → В корзину и так далее. Русские фразы могут быть длиннее, поэтому повторно проверяй строки и капсулы.

Строки ключей и ожидаемые подписи используются в тестах. Если тест ищет `Categories`, после перевода обнови и этот ожидаемый текст. В списке размеров подпись входит в ключ `size-${sizes[index]}`; переименование Small также меняет этот ключ.

### 24.13. Показать детали первым экраном

Для демонстрации можно временно заменить `MaterialApp.home`:

```dart

  coffee: coffees.first,
  favorite: false,
  onFavorite: () {},
),
```

Если это первая страница, предыдущего каталога в стеке нет. Для кнопки назад тогда следует проверять `Navigator.canPop(context)` перед `pop`. Обычная рабочая версия уже открывает детали из каталога, поэтому такое изменение для сдачи не требуется.

### 24.14. Править одну кнопку, не ломая все остальные

Если нужно увеличить только кнопки количества, меняй переданное `size: 34` в их вызовах. Если изменить размер по умолчанию в `_RoundButton`, изменятся все вызовы, где размер не задан явно.

Такое правило действует для всех общих виджетов: различай **общий шаблон** и **параметры конкретного использования**.

## 25. Ошибки новичка и способы исправления

### 25.1. Жёлто-чёрная полоса и `RenderFlex overflowed`

Это означает, что дети `Row` или `Column` требуют больше места, чем им выделено.

Если переполнение по горизонтали:

1. Найди строку, указанную в сообщении.
2. Посмотри, есть ли длинный `Text` без `Expanded` или `Flexible`.
3. Проверь фиксированные ширины и зазоры.
4. Для группы независимых коротких элементов подумай о `Wrap`.
5. Для длинного названия выбери перенос или `ellipsis`.

Если по вертикали: проверь, нужна ли экрану прокрутка, и не стоят ли слишком большие фиксированные высоты.

Не увеличивай размер эмулятора только ради сокрытия ошибки: преподаватель может запустить на другом телефонном размере.

### 25.2. `RenderFlex children have non-zero flex but incoming height constraints are unbounded`

Обычно это вертикальный `Expanded` внутри прокрутки. См. раздел 5.6. Убери такое растяжение или дай содержащему блоку конечную высоту.

Важно смотреть указанную **ось**. Горизонтальная строка с ограниченной шириной может использовать `Expanded`, даже находясь внутри вертикальной прокрутки.

### 25.3. `Incorrect use of ParentDataWidget`

Частые причины:

- `Expanded` находится в `Stack`, хотя предназначен для `Row`/`Column`/`Flex`.
- `Positioned` находится вне `Stack`.
- Между ними и нужным родителем стоит неподходящий виджет, создающий свой render object.

В наших структурах `Positioned` является непосредственным ребёнком `Stack`, `Expanded` — непосредственным ребёнком `Row` или `Column`. Сначала восстанови такую простую структуру.

### 25.4. `Unable to load asset`

Проверь:

1. Файл действительно существует.
2. Его путь совпадает с `Image.asset`.
3. Путь зарегистрирован в `pubspec.yaml`.
4. Регистр букв совпадает: `Coffee.png` и `coffee.png` могут различаться на целевой платформе.
5. В asset-пути используются `/`.
6. После изменения YAML выполнен `flutter pub get`.
7. Приложение было перезапущено, если одного reload оказалось недостаточно.

### 25.5. Красная подсветка после изменения скобок

Обычно пропущена запятая или закрывающая скобка. Смотри **первую** ошибку в файле: следующие десятки часто являются её последствиями.

В редакторе поставь курсор рядом со скобкой, чтобы увидеть пару. Используй форматирование Dart; корректная вложенность станет заметнее.

Команда для конкретного файла:

```powershell
dart format lib/coffee_app.dart
```

Форматирование не исправляет смысл программы, но выравнивает уже корректный синтаксис.

### 25.6. Ошибка о `const` после вставки переменной

Например, `const Text('$count')` использует значение, которое меняется во время работы. Убери `const` у этого `Text`. Если он находится внутри внешней `const Column` или другого константного вызова, убери соответствующий внешний `const` тоже.

Не нужно удалять `const` из всего проекта. Сохраняй его у действительно постоянных элементов.

### 25.7. Нажатие меняет данные, но экран не обновляется

Проверь наличие `setState`. Простое `_quantity++` не сообщает Flutter, что интерфейс следует перестроить.

Также проверь, не создаёшь ли счётчик внутри `build` заново, и не передан ли обработчик как `onPressed: doSomething()` вместо функции.

### 25.8. После reload стартовые значения не изменились

Используй hot restart — большую `R`. Это ожидаемое сохранение состояния. Удалять приложение или очищать весь проект для этого не нужно.

### 25.9. Каталог внезапно пустой

Проверь сочетание фильтров: текущая категория, вкладка Favorite и текст поиска. На Home нажми See all и очисти поле. Если напитки появились, проблема была в условиях фильтрации.

При добавлении напитка проверь индекс категории и название. Поиск сравнивает именно названия.

### 25.10. Картинка перекрыла надпись

Проверь порядок слоёв в `Stack` и границы `Positioned`. Если текст расположен раньше изображения, изображение рисуется поверх него. Для баннера также проверь `right: 80` у текстовой области.

### 25.11. Нижний контент спрятан под покупкой

Увеличь нижний запас `SingleChildScrollView`, если увеличилась панель. Не перемещай всю панель в прокрутку, если она должна оставаться закреплённой по макету.

### 25.12. Вместо телефона запускается Windows или браузер

Укажи `-d emulator-5554` с реальным Android-ID либо используй `tools/run-android.ps1`. Проверяй устройство через `flutter devices`.

### 25.13. Терминал не знает команду `flutter`

Проверь, что в PATH есть `D:\Soft\Flutter\flutter\bin`, затем открой новый терминал. Для разовой проверки на этом компьютере:

```powershell
& 'D:\Soft\Flutter\flutter\bin\flutter.bat' --version
```

Наличие Android Studio само по себе не означает наличие Flutter SDK в PATH.

### 25.14. Нехватка места на C или долгая загрузка Gradle

На этом компьютере для проекта подготовлены SDK и кеш на D. Запускай через скрипт, который задаёт нужные переменные своему процессу. В Android Studio может потребоваться настройка Gradle user home `D:\Android\gradle-coffee`.

`android/local.properties` содержит локальные пути SDK и Flutter. При переносе на другой компьютер их нужно настроить под новую машину.

Не начинай с `flutter clean` при каждой проблеме цвета или отступа: удаление результатов сборки увеличит время следующего запуска и не исправит вёрстку.

### 25.15. Сборка не запускается — что прочитать

```powershell
flutter doctor -v
flutter devices
flutter analyze
```

Первая команда проверяет окружение, вторая — устройства, третья — Dart-код. В журнале сборки ищи исходную ошибку перед итоговым `BUILD FAILED`, а не только последнюю строку.

Для этой лабораторной не требуется настраивать инструменты для всех платформ Flutter: важен рабочий Android-путь.

## 27. Как объяснить работу на защите

Ниже ответы простыми словами. Лучше понять их по коду, чем заучивать дословно.

**Что было нужно сделать?**

Сверстать два мобильных экрана по макету: каталог кофе и страницу напитка. Сохранить порядок и выравнивание элементов, подобрать похожие цвета, изображения и иконки.

**Почему Flutter?**

Это технология задания. Интерфейс описывается на Dart через дерево виджетов. Приложение запускается на Android-эмуляторе.

**Чем `Row` отличается от `Column`?**

`Row` располагает детей горизонтально, `Column` — вертикально. Главная и поперечная оси у них меняются местами.

**Зачем `Expanded`?**

Чтобы выделить ребёнку оставшееся место внутри строки или колонки. В поиске он отдаёт полю всю ширину после круглой кнопки, в карточке — оставшуюся высоту изображению.

**Зачем `Stack`?**

Для наложения элементов. В баннере картинка и текст стоят поверх фона, в карточке сердце лежит над картинкой, в деталях стакан перекрывает декоративную надпись и два фоновых слоя.

**Как закреплена нижняя навигация?**

Она находится в `Scaffold.bottomNavigationBar`, отдельно от прокручиваемого содержимого.

**Как закреплена кнопка покупки?**

Это последний слой внешнего `Stack` с `Positioned(bottom: 0)`. Прокрутке добавлен нижний отступ, чтобы её содержимое не скрывалось под панелью.

**Почему у каталога `CustomScrollView` и slivers?**

Чтобы верхние блоки и сетка карточек участвовали в одной прокрутке. Верх построен `SliverList`, товары — `SliverGrid`.

**Почему для флажков используется `Wrap`?**

На узком экране опции переносятся на следующую строку, сохраняя порядок.

**Чем StatefulWidget отличается от StatelessWidget?**

У StatefulWidget есть связанный объект State для изменяемых данных. StatelessWidget строит интерфейс по переданной конфигурации. Он тоже может перестраиваться, если родитель передаёт новые значения.

**Что делает `setState`?**

Внутри меняется значение, например количество, а Flutter получает запрос перестроить интерфейс с новым значением.

**Как передаются данные между экранами?**

При открытии деталей через Navigator передаётся объект Coffee, состояние избранного и callback изменения избранного.

**Откуда изображения?**

Из Pinterest, ссылки сохранены в `docs/image-sources.md`. Изображения подготовлены как локальные PNG и подключены через assets. Генерация изображений в проекте не использовалась.

**Почему часы отличаются от макета?**

Это реальные системные панели Android. На исходном изображении показан другой внешний вид телефона; время и системные значки не являются нарисованными элементами нашего экрана.

**Есть ли настоящая корзина и сервер?**

Нет. Для лабораторной сделана вёрстка и локальные действия. Add to Cart показывает подтверждение, флажки изменяют выделение, данные живут в памяти. Это нужно описывать честно.

**Как считалась цена?**

Использована демонстрационная формула из раздела 20.4. Для Espresso Large показывает $2, Small $1.50 за одну порцию, итог умножается на количество.

**Как проверялась работа?**

Статический анализ, widget-тесты на двух размерах и запуск на Android-эмуляторе. Визуальное соответствие проверяется отдельно по экрану и макету.

### 28.2. Пять вопросов перед каждой правкой

1. **Кто родитель?** Он может ограничивать размер.
2. **По какой оси нужно изменение?** Для `Row` и `Column` оси разные.
3. **Меняю блок или его содержимое?** Отступ картинки и отступ карточки — разные вещи.
4. **Это общий виджет или один вызов?** Общий класс может использоваться во многих местах.
5. **Нужен reload или restart?** Вёрстку обычно видно после reload, стартовое состояние — после restart.
